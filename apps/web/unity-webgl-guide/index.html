03 빌드 전 설정

빌드 옵션 설정

Code Optimization: Runtime Speed with LTO → Runtime Speed → Speed 순으로, 있는 항목을 선택하세요.

문제 분석용 옵션이 필요할 때

Profiler로 분석할 때만 Development Build와 Autoconnect Profiler를 켭니다. Deep Profiling은 상세 진단이 필요할 때만 사용하세요. 제출 전에는 일반 빌드로 되돌리고, 숨겨지거나 회색인 진단 옵션은 그대로 둡니다.

한줄요약

05 빌드 전 설정

텍스처와 그래픽 설정

PC 브라우저용: Player의 Texture compression format은 DXT, 빌드 창은 Use Player Settings로 둡니다.

선택 사항 · 그래픽 품질과 성능 조정

Web에 사용할 품질 단계의 Render Pipeline Asset을 선택하세요. 없으면 Graphics의 기본 에셋을 확인합니다. Built-in 프로젝트는 Quality의 설정을 사용합니다.

  • Render Scale을 낮추면 처리량이 줄지만 화면이 덜 선명해집니다.
  • AA/MSAA를 높이면 가장자리가 매끄러워지고 처리 비용이 늘어납니다.
  • 그림자 거리·캐스케이드는 표현과 성능을 함께 비교하세요.
  • HDR·Opaque Texture는 필요한 효과가 없을 때만 끕니다.

한 번에 하나씩 바꾸고 같은 장면에서 비교하세요. 효과가 없거나 표현이 깨지면 되돌립니다. URP 성능 ↗

한줄요약

텍스처 압축은 DXT입니다. 품질은 필요할 때 측정하며 조정하세요.

06 빌드·업로드

빌드 실행·결과 폴더 확인

  1. Build Profiles의 활성 Web 프로필에서Build Settings의 WebGL에서 Build를 누릅니다.
  2. 새 빈 폴더를 만들어 저장 위치로 선택합니다. 예: MyGame-Web-01.
  3. 완료 후 결과 폴더의 index.html과 Build 폴더를 확인합니다. 중단되면 빌드 도움말로 이동하세요.

다음 단계에서는 Assets·Packages가 있는 프로젝트 원본이 아닌 빌드 결과물을 압축합니다. index.html을 더블클릭하지 말고 업로드 후 실행을 확인하세요.

한줄요약

빌드가 완료됐고, 결과 폴더에 index.html과 Build가 있습니다.

다음: ZIP 만들기 →
07 빌드·업로드

빌드 결과물 ZIP 압축

  1. 결과 폴더에서 index.html이 보이는 위치를 엽니다.
  2. 파일·폴더 전부를 선택합니다. Windows: Ctrl+A / macOS: Command+A.
  3. 우클릭 → ZIP 압축을 선택합니다. Windows: ‘ZIP 파일로 압축’ 또는 ‘보내기 → 압축(ZIP) 폴더’ / macOS: ‘압축’.
  4. ZIP 안에 index.html·Build와 생성된 모든 결과물이 함께 있는지 확인합니다.
MyGame-Web-01.zip
├─ index.html
├─ Build/
│  ├─ ….loader.js
│  ├─ ….framework.js.br
│  ├─ ….wasm.br
│  └─ ….data.br
├─ TemplateData/         ← 생성되었다면 함께 포함
└─ StreamingAssets/      ← 생성되었다면 함께 포함

구조와 이름은 예시입니다. 파일 일부만 압축하거나 프로젝트 원본을 올리지 마세요. 생성된 파일·확장자·JavaScript는 수정하지 않습니다.

이미 바깥 폴더를 포함해 압축했다면

바깥 폴더 하나 안에 결과물 전체가 있는 구조도 업로드 안내에 포함되어 있습니다. 여러 겹으로 감싸거나 일부 파일을 바깥에 두지 마세요.

한줄요약

빌드 결과물 전체가 담긴 ZIP 하나가 준비되었습니다.

09 실행·성능 확인

업로드본 실행·기능 확인

  1. 로그인 → 전시 목록 → 제출한 전시회 → 내 작품을 엽니다.
  2. 플레이해보기를 누르고 로딩을 기다립니다. 버튼이 없거나 실행이 멈추면 실행 도움말로 이동하세요.
  3. 이번 업로드본에서 게임 시작·주요 조작·장면 전환을 확인합니다. 실제 플레이 구간까지 진행하세요.
  4. ZIP 파일명·실행 주소를 기록합니다. 멈추면 화면과 직전 행동을 함께 적으세요.
  5. 수정했다면 새로 빌드 → ZIP → 업로드 → 실행 확인을 반복합니다.
한줄요약

이번 ZIP의 업로드본에서 시작과 주요 기능을 확인했습니다.

11 실행·성능 확인

초기 로딩·플레이 성능·메모리 구분

처음 게임이 뜨기까지 오래 걸려요

기본 경로의 Brotli + Fallback OFF로 빌드하고, 초기 씬에 넣은 에셋의 크기를 줄여 비교합니다. Disk Size with LTO도 비교 후보입니다. 플레이 중 FPS와 별도로 시간을 기록하세요.

로딩은 끝났는데 게임이 버벅거려요

릴리스 빌드인지 확인하고, 같은 장면에서 Render Scale·그림자·MSAA를 하나씩 낮춰 비교합니다. 효과가 없다면 Profiler로 CPU 처리를 확인합니다. Brotli로 바꾸는 것만으로 해결될 종류의 문제는 아닐 수 있습니다.

30 FPS 근처에 일정하게 머물러요

개발자가 설정한 목표 FPS, 브라우저·디스플레이의 프레임 동작도 확인해야 합니다. 일정한 제한인지, 처리 시간이 길어 목표를 못 맞추는지 구분한 후 최적화하세요.

압축 파일 파싱 오류 또는 검은 화면이 나와요

실제 실행 페이지의 오류 메시지와 선택한 압축 조합을 기록하세요. 기본 설정의 조합으로 만든 빌드에서 반복된다면 실행 주소·Unity 버전·오류 화면을 카카오톡 Bipolar_로 전달하세요. 원인 비교가 필요할 때만 Disabled로 한 번 더 빌드할 수 있습니다. 파일 이름을 바꾸거나 생성된 JavaScript를 편집하는 방식으로 해결하지 마세요.

메모리를 최대치로 키우면 빨라지나요?

아닙니다. 메모리 사용량을 측정하고 필요한 만큼 조정합니다. 텍스처와 초기 에셋 규모부터 살피세요. 허용 최대치를 늘리는 것과 실제 사용량을 줄이는 것은 다릅니다.

한줄요약

로딩·플레이·메모리 중 병목을 구분했습니다. 설정을 바꿨다면 다시 빌드·업로드해 같은 조건으로 비교하세요.

문제 발생 단계별 도움말

Unity에서 빌드가 완료되지 않습니다

먼저 확인: Web/WebGL 플랫폼과 설치 모듈을 확인하고, Unity Console에 오류가 보이면 그 문구를 캡처하세요. 빌드가 끝나지 않은 결과물은 압축·업로드하지 마세요.

계속 안 되면: Unity 버전, 오류 화면, Build를 누르기 전후의 행동을 문의 정보와 함께 정리해 카카오톡 Bipolar_로 문의하세요.

ZIP 업로드가 거절되거나 완료되지 않습니다

먼저 확인: 7단계의 전체 결과물 ZIP인지, 기타 파일에서 WebGL로 골랐는지 확인하세요. 화면에 표시된 파일 제한·입력 오류·전시회 잠금 안내를 읽습니다. 업로드가 끊겨 같은 원본 파일을 다시 고르라는 안내가 나오면 바로 그 ZIP을 선택하세요.

계속 안 되면: ZIP 파일명·크기, 막힌 화면, 표시된 오류와 직전 행동을 정리해 카카오톡 Bipolar_로 문의하세요. 전시회가 없거나 잠긴 경우에도 같은 경로로 문의하세요. 기록할 정보와 문의 경로를 확인하세요. 실행 주소는 아직 없으면 쓰지 않아도 됩니다.

업로드는 됐지만 로딩이 멈추거나 검은 화면이 나옵니다

먼저 확인: 이번 업로드의 처리가 완료됐는지 확인하고 작품의 플레이해보기로 다시 엽니다. 브라우저를 최신 상태로 사용하고, 그래픽 가속 안내가 나오면 그 안내를 따르세요. 생성된 파일을 직접 고치지 마세요.

계속 안 되면: 카카오톡 Bipolar_로 작품명, 실행 주소가 있다면 그 주소, 브라우저 이름·버전, 오류 문구 또는 멈춘 화면을 전달합니다. 실행 버튼이 없는 경우에는 그 작품 화면을 기록합니다. 원인을 추측하지 않고 진행한 순서를 알려주세요.

게임 화면은 나오지만 시작 버튼 이후 또는 특정 행동에서 멈춥니다

먼저 확인: 어떤 버튼·조작 뒤 멈추는지 다시 확인하고 순서대로 적습니다. 씬 전환에서 멈췄다면 필요한 씬이 2단계의 목록에 체크되어 있는지 확인하세요.

계속 안 되면: 멈춘 화면과 재현 순서를 문의 정보에 포함해 카카오톡 Bipolar_로 문의하세요. 코드·서버 문제를 미리 판정할 필요는 없습니다.

게임은 실행되지만 느리거나 끊깁니다

먼저 확인: Development Build가 꺼진 이번 업로드본인지, 브라우저 그래픽 가속 안내가 있는지 확인합니다. 느려지는 장면과 그때의 조작을 기록하세요.

계속 안 되면: 브라우저·사용 기기, 느려지는 장면, 재현 순서를 문의 정보와 함께 카카오톡 Bipolar_로 전달하세요. 직접 개선하려면 FPS·메모리 참고와 그래픽 참고를 읽습니다. 측정부터 마쳐야 문의할 수 있는 것은 아닙니다.

문의할 때 전달할 내용
  • 막힌 단계와 작품명
  • Unity 버전, 브라우저 이름·버전(브라우저 실행 전이면 ‘아직 실행 전’)
  • 실행 주소가 생성됐다면 그 주소. 빌드·업로드 단계에서 주소가 없으면 생략
  • 오류 문구가 있으면 문구가 보이는 화면, 문구 없이 멈추면 멈춘 화면
  • 멈추기 직전에 한 행동과 다시 재현하는 순서

문의 경로: 카카오톡 ID Bipolar_로 문의하세요. 카카오톡 ID 검색에서 Bipolar_를 찾아 연락하세요. 위의 문의 정보를 함께 보내주세요. 서버 설정이나 HTTP 헤더를 조사할 필요는 없습니다.
