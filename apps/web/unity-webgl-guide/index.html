02 프로젝트 준비

빌드 씬·시작 순서 설정

씬 이름과 내용은 내 프로젝트에 맞게 정하세요. Addressables·커스텀 로더를 쓰면 기존 로딩 구성을 유지하세요.

한줄요약

필요한 씬이 체크되어 있고, 시작 씬이 0번입니다.

다음: 빌드 옵션 설정 →
03 빌드 전 설정

빌드 옵션 설정

Code Optimization: Runtime Speed with LTO → Runtime Speed → Speed 순으로, 있는 항목을 선택하세요.

문제 분석용 옵션이 필요할 때

Profiler로 분석할 때만 Development Build와 Autoconnect Profiler를 켭니다. Deep Profiling은 상세 진단이 필요할 때만 사용하세요. 제출 전에는 일반 빌드로 되돌리고, 숨겨지거나 회색인 진단 옵션은 그대로 둡니다.

한줄요약

Development Build는 OFF, Code Optimization은 실행 속도 설정입니다.

다음: Player·압축·메모리 →
04 빌드 전 설정

Player 설정: 압축·템플릿·메모리

Edit → Project Settings → Player → WebWebGL

아래 세 장과 똑같이 설정하면 됩니다. 이미지를 눌러 크게 보세요.

Web Build의 동작 방식과 각 옵션의 의미를 알고 있다면 프로젝트에 맞게 설정해도 됩니다. PWA 다운로드 기능과 중첩 Unity 앱 구조를 제외하면 대부분 지원됩니다.
한줄요약

압축·Fallback·템플릿을 정하고 필요한 메모리·진단 옵션을 확인했습니다.

다음: 텍스처·그래픽 설정 →
05 빌드 전 설정

텍스처와 그래픽 설정

PC 브라우저용: Player의 Texture compression format은 DXT, 빌드 창은 Use Player Settings로 둡니다.

선택 사항 · 그래픽 품질과 성능 조정

Web에 사용할 품질 단계의 Render Pipeline Asset을 선택하세요. 없으면 Graphics의 기본 에셋을 확인합니다. Built-in 프로젝트는 Quality의 설정을 사용합니다.

  • Render Scale을 낮추면 처리량이 줄지만 화면이 덜 선명해집니다.
  • AA/MSAA를 높이면 가장자리가 매끄러워지고 처리 비용이 늘어납니다.
  • 그림자 거리·캐스케이드는 표현과 성능을 함께 비교하세요.
  • HDR·Opaque Texture는 필요한 효과가 없을 때만 끕니다.

한 번에 하나씩 바꾸고 같은 장면에서 비교하세요. 효과가 없거나 표현이 깨지면 되돌립니다. URP 성능 ↗

한줄요약

텍스처 압축은 DXT입니다. 품질은 필요할 때 측정하며 조정하세요.

06 빌드·업로드

빌드 실행·결과 폴더 확인

  1. Build Profiles의 활성 Web 프로필에서Build Settings의 WebGL에서 Build를 누릅니다.
  2. 새 빈 폴더를 만들어 저장 위치로 선택합니다. 예: MyGame-Web-01.
  3. 완료 후 결과 폴더의 index.html과 Build 폴더를 확인합니다. 중단되면 빌드 도움말로 이동하세요.

다음 단계에서는 Assets·Packages가 있는 프로젝트 원본이 아닌 빌드 결과물을 압축합니다. index.html을 더블클릭하지 말고 업로드 후 실행을 확인하세요.

한줄요약

빌드가 완료됐고, 결과 폴더에 index.html과 Build가 있습니다.

다음: ZIP 만들기 →
07 빌드·업로드

빌드 결과물 ZIP 압축

  1. 결과 폴더에서 index.html이 보이는 위치를 엽니다.
  2. 파일·폴더 전부를 선택합니다. Windows: Ctrl+A / macOS: Command+A.
  3. 우클릭 → ZIP 압축을 선택합니다. Windows: ‘ZIP 파일로 압축’ 또는 ‘보내기 → 압축(ZIP) 폴더’ / macOS: ‘압축’.
  4. ZIP 안에 index.html·Build와 생성된 모든 결과물이 함께 있는지 확인합니다.
MyGame-Web-01.zip
├─ index.html
├─ Build/
│  ├─ ….loader.js
│  ├─ ….framework.js.br
│  ├─ ….wasm.br
│  └─ ….data.br
├─ TemplateData/         ← 생성되었다면 함께 포함
└─ StreamingAssets/      ← 생성되었다면 함께 포함

구조와 이름은 예시입니다. 파일 일부만 압축하거나 프로젝트 원본을 올리지 마세요. 생성된 파일·확장자·JavaScript는 수정하지 않습니다.

이미 바깥 폴더를 포함해 압축했다면

바깥 폴더 하나 안에 결과물 전체가 있는 구조도 업로드 안내에 포함되어 있습니다. 여러 겹으로 감싸거나 일부 파일을 바깥에 두지 마세요.

한줄요약

빌드 결과물 전체가 담긴 ZIP 하나가 준비되었습니다.

09 실행·성능 확인

업로드본 실행·기능 확인

  1. 로그인 → 전시 목록 → 제출한 전시회 → 내 작품을 엽니다.
  2. 플레이해보기를 누르고 로딩을 기다립니다. 버튼이 없거나 실행이 멈추면 실행 도움말로 이동하세요.
  3. 이번 업로드본에서 게임 시작·주요 조작·장면 전환을 확인합니다. 실제 플레이 구간까지 진행하세요.
  4. ZIP 파일명·실행 주소를 기록합니다. 멈추면 화면과 직전 행동을 함께 적으세요.
  5. 수정했다면 새로 빌드 → ZIP → 업로드 → 실행 확인을 반복합니다.

외부 API·멀티플레이 연결 신청

내 작품 → 외부 연결에서 호스트명과 HTTPS/WSS 방식을 선택해 신청합니다. 새 신청은 모든 포트가 기본이며 특정 포트는 고급 설정에서 지정합니다. 하위 도메인 범위는 루트 호스트를 포함하지 않습니다. URL의 숫자 포트는 설정과 일치해야 하며 경로·쿼리·자격 증명은 허용하지 않습니다.

기존 사용 목적·서버 설정 계획에 SDK/버전·게임 모드, 목적지별 용도, 인증 방식(비밀정보 제외), 외부 서비스 운영 담당자와 2인 플레이 확인 절차를 적으세요. CORS·Origin 검사·인증은 외부 서비스 담당자가 설정해야 합니다.

신청 → 관리자 승인 → 새 실행 순서로 진행합니다. 기존 승인과 겹치면 철회 후 새 승인이 필요하며 기존 플레이의 이후 파일 요청·갱신이 거절됩니다. 승인 후 서로 다른 두 계정으로 같은 방에 접속해 양방향 게임 상태와 재접속을 확인하세요. 서비스 예시는 Photon/Relay 연동 보장이 아닙니다.

현재 마감 후에는 새 연결 신청이 제한되며, 실행 중 API 갱신이 실패하면 게임이 종료됩니다. 마감 후 권한과 일시적 실패 재시도는 후속 개선 항목입니다.

10 실행·성능 확인

실행 후 FPS·메모리 측정

측정은 선택 사항이며 공통 FPS 합격선은 없습니다. 커스텀 템플릿에는 진단 버튼이 없을 수 있습니다.

한줄요약
