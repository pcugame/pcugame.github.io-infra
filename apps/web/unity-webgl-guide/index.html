01 프로젝트 준비

Unity 버전·빌드 플랫폼 설정

Unity Hub의 Projects 목록에서 내 프로젝트의 Editor Version을 확인한 뒤, 이 문서 상단에서 내 프로젝트의 버전을 선택하세요. 선택한 버전에 맞는 메뉴와 화면을 아래에서 확인하세요.

File → Build Profiles → Platforms → Web

Web → Switch Platform 을 누릅니다. 이미 Active면 그대로 둡니다. 별도로 만든 Web 프로필을 쓰고 있다면 그 프로필을 선택해 Switch Profile 을 누르세요.

File → Build Settings → WebGL → Switch Platform

WebGL을 선택하고 Switch Platform 을 누릅니다. 이미 WebGL이 활성 플랫폼이면 그대로 둡니다.

Web 플랫폼이 없거나 모듈이 필요하다는 메시지가 나오면 건너뛰지 마세요. Unity Hub → Installs → 현재 사용하는 에디터의 메뉴 → Add modules에서 Web Build SupportWebGL Build Support 를 설치한 뒤 다시 전환하세요.

02 프로젝트 준비

빌드 씬·시작 순서 설정

Build Profiles에서 Scene List / Open Scene List 를 엽니다. 별도 빌드 프로필을 사용한다면 그 프로필이 실제로 사용하는 씬 목록을 확인하세요.

Build Settings 창 위쪽의 Scenes In Build 목록을 확인하세요.

  1. 게임에서 사용하는 씬이 목록에 있는지 확인합니다. 빠진 씬은 Project 창에서 목록으로 드래그하거나, 씬을 열고 Add Open Scenes 를 누릅니다.
  2. 빌드에 포함할 씬의 체크박스를 켭니다.
  3. 게임을 켰을 때 처음 보여줄 화면의 씬 을 활성 목록의 첫 번째인 0번 으로 둡니다. 필요한 경우 드래그해 순서를 바꾸세요.
  4. 시작 화면만 넣지 말고, 게임을 진행하면서 불러올 다른 필요한 씬도 포함하고 체크합니다.

이 설명은 일반적인 씬 목록 기반 프로젝트의 절차입니다. Addressables 등 별도 로딩 구조로 관리하는 씬까지 무조건 이 목록에 넣으라는 뜻은 아닙니다. 그런 프로젝트는 기존 로딩 구성을 유지하세요.

한줄요약

필요한 씬이 체크되어 있고, 처음 보여줄 씬이 0번입니다.

      Compression Format Brotli
      Decompression Fallback OFF · 체크 해제
      Enable Native C/C++ Multithreading 항목이 있으면 OFF . 없는 버전에서는 찾느라 진행을 멈추지 마세요.

      내 상황 Compression Format Decompression Fallback
      첫 제출 기본 / 다운로드 크기 줄이기 Brotli OFF
      자주 빌드해서 업로드·플레이 확인 Gzip OFF

      특정 압축 형식을 제출 조건으로 강제하지 않습니다. 새로 만든다면 위의 첫 두 조합을 사용하세요. Brotli/Gzip은 주로 다운로드 크기와 로딩에 영향을 줍니다. 플레이 중 FPS가 낮다고 Fallback을 켜지는 마세요.

      Publishing Settings 위치

      Player에서 Web 아이콘을 선택한 뒤 아래로 스크롤합니다. 접혀 있는 Publishing Settings 제목을 클릭해 펼치세요.

      공통 설정의 위치를 확인하는 화면입니다. 화면 속 예시 값을 모두 복사하지 말고 , 항목별 안내 값을 적용하세요. 여기서 버튼을 눌러도 Unity 프로젝트 설정은 바뀌지 않습니다.

      목록을 스크롤해 항목을 선택하세요. 사진 우측 상단의 사진 확대 버튼으로 선택한 위치를 크게 볼 수 있습니다.

        설정한 뒤에는 실제 업로드 페이지에서 플레이하세요.
        로딩 완료, 조작, 장면 전환을 확인합니다. 이 확인은 내 게임의 동작을 검증하는 단계입니다. 사용자가 압축 전송 방식이나 호스팅 설정을 조사할 필요는 없습니다.

        압축은 다운로드·시작 시간, Power Preference는 GPU 선택 힌트에 관련됩니다. 예외·메모리는 기본값을 출발점으로 삼고 문제가 있을 때 측정하며 조정하세요. 배포·압축 ↗ 메모리 ↗

        Default, Minimal, PWA의 차이

        Default는 처음 제출할 때 사용할 기본 템플릿입니다. Minimal은 기본 버튼 없이 게임 화면을 배치하려는 경우의 선택입니다. PWA는 설치·오프라인 기능을 위한 출력 구조입니다. 확인한 사이트 소스에서는 PWA의 설치·오프라인 기능을 지원하지 않습니다. 이것만으로 PWA 출력물의 기본 Unity 게임도 모두 실행 불가능하다는 뜻은 아닙니다. 기본 플레이어의 실행과 추가 PWA 기능은 별도로 확인해야 합니다.

        Default Canvas Width / Height는 시작 크기입니다. 실제 렌더링 해상도는 브라우저 창과 기기의 픽셀 비율에 따라 달라질 수 있습니다.

        URP 그래픽 설정 비교 순서

        Quality에서 Render Pipeline Asset 찾기

        Edit → Project Settings → Quality를 엽니다. Web에 적용할 품질 단계를 선택하고 Rendering의 Render Pipeline Asset 을 누르세요. 에셋이 없으면 Graphics의 기본 에셋을 확인합니다. 아래 공식 화면은 위치를 보여주는 Windows 예시이므로 PC라는 이름을 그대로 따라 만들 필요는 없습니다.

        Project Settings → Quality 에서 Web에 사용할 품질 단계와 연결된 Render Pipeline Asset 을 확인합니다. 해당 에셋을 Project 창에서 선택해 Inspector에서 아래 항목을 찾으세요. Quality에 별도 에셋이 없으면 Graphics의 기본 Render Pipeline Asset을 확인합니다.

        Inspector에서 찾을 항목 비교할 변경 확인할 점
        Quality → Render Scale 1.0 → 0.75 예시 화면 선명도와 FPS. GPU 병목일 때 유효한 후보입니다.
        Quality → Anti Aliasing (MSAA) 4×/8× → 2× 또는 Disabled 모서리의 계단 현상이 허용되는지 확인합니다.
        Shadows → Max Distance / Cascade Count 거리·단계 축소 그림자가 사라지는 거리와 화질을 확인합니다.
        Additional Lights → Cast Shadows 필요 없으면 OFF 게임 표현에 필요한 그림자는 남깁니다.
        HDR / Opaque Texture 해당 기능이 불필요할 때만 OFF 블룸·굴절 등 의존하는 효과가 깨지지 않는지 확인합니다.

        위 숫자는 측정을 위한 비교 예시입니다. 모든 프로젝트의 권장 최종값은 아닙니다. Built-in Render Pipeline 프로젝트라면 URP 에셋이 없는 것이 정상이며, Project Settings → Quality에서 해당 그래픽 품질을 조절합니다. URP 성능 ↗ URP 에셋 ↗

        바꾸기 전 값을 기록하고, 한 번에 하나만 바꾸세요.
        같은 카메라·같은 장면에서 비교해야 어떤 옵션이 효과가 있었는지 알 수 있습니다. Render Scale을 낮춰도 차이가 없다면 CPU 처리나 프레임 제한 등 다른 원인을 살펴야 합니다.

        같은 장면·같은 창 크기에서 변경 전후를 비교하세요. 효과가 없거나 화면 표현이 깨지면 원래 값으로 되돌립니다. 변경을 유지해 제출한다면 새로 빌드·압축·업로드·실행 확인을 마치세요.

        07 빌드·업로드

        빌드 결과물 ZIP 압축

        1. 방금 만든 빌드 결과 폴더를 열어 index.html이 보이는 위치 로 이동합니다.
        2. 그 위치의 파일과 폴더를 전부 선택 합니다. Windows는 Ctrl+A, macOS는 Command+A를 사용합니다.
        3. 선택한 항목을 우클릭하고 운영체제의 ZIP 압축 명령을 사용합니다. Windows는 ‘ZIP 파일로 압축’ 또는 ‘보내기 → 압축(ZIP) 폴더’, macOS는 ‘압축’을 선택합니다.
        4. 완성된 ZIP에 이름을 붙이고 파일명과 저장 위치를 기억하세요. 예: MyGame-Web-01.zip . 압축 파일 안에서 index.html과 Build 등 모든 결과물이 함께 있는지 확인합니다.

        Unity 프로젝트 원본 전체, index.html 하나, Build 폴더 하나만 올리는 것이 아닙니다. 빌드 결과물 전체를 함께 압축합니다. StreamingAssets나 예시에 없는 추가 파일·폴더도 생성되었다면 모두 포함하세요. 

        MyGame-Web-01.zip
├─ index.html
├─ Build/
│  ├─ ….loader.js
│  ├─ ….framework.js.br
│  ├─ ….wasm.br
│  └─ ….data.br
├─ TemplateData/         ← 생성되었다면 함께 포함
└─ StreamingAssets/      ← 생성되었다면 함께 포함

        위 구조와 이름은 예시 입니다. 없는 파일을 새로 만들거나 실제 출력 파일을 지우지 마세요. 확장자, loader, 생성된 JavaScript는 직접 고치지 않습니다.

        이미 다른 압축 방식으로 ZIP을 만든 경우

        위 방법은 ZIP을 열자마자 index.html이 보이게 만듭니다. 업로드 안내에는 바깥 폴더 하나 안에 전체 결과물이 들어 있는 구조도 제시되어 있습니다. 여러 폴더를 임의로 더 감싸거나 파일 일부를 바깥에 두지 마세요. 다른 정상 압축 조합의 허용 여부는 이 기본 절차로 바뀌지 않습니다.

        한줄요약

        업로드할 ZIP 하나가 준비되었고, 그 안에 빌드 결과물 전체가 들어 있습니다.

        처음 게임이 뜨기까지 오래 걸려요

        기본 경로의 Brotli + Fallback OFF로 빌드하고, 초기 씬에 넣은 에셋의 크기를 줄여 비교합니다. Disk Size with LTO도 비교 후보입니다. 플레이 중 FPS와 별도로 시간을 기록하세요.

        로딩은 끝났는데 게임이 버벅거려요

        릴리스 빌드인지 확인하고, 같은 장면에서 Render Scale·그림자·MSAA를 하나씩 낮춰 비교합니다. 효과가 없다면 Profiler로 CPU 처리를 확인합니다. Brotli로 바꾸는 것만으로 해결될 종류의 문제는 아닐 수 있습니다.

        30 FPS 근처에 일정하게 머물러요

        개발자가 설정한 목표 FPS, 브라우저·디스플레이의 프레임 동작도 확인해야 합니다. 일정한 제한인지, 처리 시간이 길어 목표를 못 맞추는지 구분한 후 최적화하세요.

        압축 파일 파싱 오류 또는 검은 화면이 나와요

        실제 실행 페이지의 오류 메시지와 선택한 압축 조합을 기록하세요. 기본 설정의 조합으로 만든 빌드에서 반복된다면 실행 주소·Unity 버전·오류 화면을 카카오톡 Bipolar_로 전달하세요. 원인 비교가 필요할 때만 Disabled로 한 번 더 빌드할 수 있습니다. 파일 이름을 바꾸거나 생성된 JavaScript를 편집하는 방식으로 해결하지 마세요.

        메모리를 최대치로 키우면 빨라지나요?

        아닙니다. 메모리 사용량을 측정하고 필요한 만큼 조정합니다. 텍스처와 초기 에셋 규모부터 살피세요. 허용 최대치를 늘리는 것과 실제 사용량을 줄이는 것은 다릅니다.

        먼저 확인: Development Build가 꺼진 이번 업로드본인지, 브라우저 그래픽 가속 안내가 있는지 확인합니다. 느려지는 장면과 그때의 조작을 기록하세요.

        계속 안 되면: 브라우저·사용 기기, 느려지는 장면, 재현 순서를 문의 정보 와 함께 카카오톡 Bipolar_로 전달하세요. 직접 개선하려면 FPS·메모리 참고 와 그래픽 참고 를 읽습니다. 측정부터 마쳐야 문의할 수 있는 것은 아닙니다.
