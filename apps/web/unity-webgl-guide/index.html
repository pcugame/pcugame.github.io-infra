FAQ

꼭 해야하나요?

기본적으로 많은 사람들이 게임을 쉽게 즐겨볼 수 있게 하자는 취지에서 만들어진 기능입니다. 업로드를 권장합니다. 매 해 제반 상황이 다를 수 있으므로, 만약 정말 하기 어려운 상황이라면 담임 교수님께 여쭤보세요.

유니티 빌드가 아니에요

직접 호스팅한 뒤 링크 추가 기능으로 등록하거나, 업로드하지 않아도 됩니다.

제 컴퓨터에서는 영상·사진이 나오는데, 업로드하면 안 나와요

코드에 C:/Users/..., file://...처럼 내 컴퓨터의 경로를 적었는지 확인하세요. 웹에서 실행하는 게임은 그 경로로 개발자 PC의 파일을 읽을 수 없습니다. Assets/...라는 프로젝트 경로를 적는 것만으로도 웹에서 파일을 불러올 수는 없습니다.

파일을 빌드에 포함하고, 웹에서 읽을 수 있는 방식으로 불러오도록 코드를 수정하세요. 원본 파일을 그대로 읽어야 한다면 Assets/StreamingAssets에 넣고 Application.streamingAssetsPath를 기준으로 주소를 만드세요. 빌드 결과의 StreamingAssets 폴더도 ZIP에 포함해야 합니다. 수정 후에는 다시 빌드·업로드하세요. 

// 잘못된 예: 개발자 PC나 프로젝트 폴더를 직접 가리킵니다.
string wrongPath = "C:/Users/Me/Pictures/photo.png";

// 수정 예: Assets/StreamingAssets/photo.png를 빌드에 포함합니다.
string imageUrl = Application.streamingAssetsPath + "/photo.png";
// 이 주소를 아래의 이미지 다운로드 코드에 사용하세요.

사진을 File.ReadAllBytes로 읽었는데 Web 빌드에서는 안 보여요

Web 빌드의 StreamingAssets 경로는 웹 주소입니다. File.ReadAllBytes 같은 파일 읽기 코드로 직접 접근할 수 없습니다. PNG·JPG를 실행 중 불러오려면 UnityWebRequestTexture.GetTexture로 요청하고, 다운로드 완료와 성공 여부를 확인한 뒤 받은 텍스처를 화면에 적용하세요.

파일 주소와 실제 파일명의 대소문자도 확인하세요. 다운로드가 끝나기 전에 이미지를 사용하거나, 요청 실패를 확인하지 않으면 빈 화면만 보일 수 있습니다.

WebImageLoader.cs로 저장해 활성 게임 오브젝트에 붙이고, Inspector의 Target에 UI의 RawImage를 연결하세요. 사진은 Assets/StreamingAssets/photo.png에 넣습니다. 

using System.Collections;
using UnityEngine;
using UnityEngine.Networking;
using UnityEngine.UI;

public class WebImageLoader : MonoBehaviour
{
    [SerializeField] private RawImage target;
    private Texture2D loadedTexture;

    private IEnumerator Start()
    {
        string url = Application.streamingAssetsPath + "/photo.png";
        using (var request = UnityWebRequestTexture.GetTexture(url))
        {
            yield return request.SendWebRequest();
            if (request.result != UnityWebRequest.Result.Success)
            {
                Debug.LogError(request.error);
                yield break;
            }

            loadedTexture = DownloadHandlerTexture.GetContent(request);
            target.texture = loadedTexture;
        }
    }

    private void OnDestroy()
    {
        if (loadedTexture != null) Destroy(loadedTexture);
    }
}

VideoPlayer에 영상을 넣었는데 Web 빌드에서는 재생이 안 돼요

VideoPlayer.clip에 VideoClip을 넣어 재생하는 방식은 WebGL에서 지원되지 않습니다. VideoPlayer의 Source를 URL로 바꾸고, videoPlayer.url에 웹에서 접근할 수 있는 영상 주소를 지정하세요.

빌드에 포함할 영상은 Assets/StreamingAssets에 넣고, Application.streamingAssetsPath를 기준으로 영상 주소를 만드세요. 내 컴퓨터의 절대 경로를 넣지 말고, 빌드 결과의 영상 파일까지 함께 압축해 업로드하세요. URL을 수정해도 재생되지 않으면 브라우저가 지원하는 영상 형식인지도 확인하세요.

WebVideoPlayer.cs로 저장하고, Inspector의 Player에 VideoPlayer를 연결하세요. 영상은 Assets/StreamingAssets/intro.mp4에 넣습니다. VideoPlayer의 Play On Awake를 끄고 화면 출력 대상도 설정한 뒤, UI 버튼의 On Click에 아래 PlayVideo()를 연결하세요. 

using UnityEngine;
using UnityEngine.Video;

public class WebVideoPlayer : MonoBehaviour
{
    [SerializeField] private VideoPlayer player;

    private void Awake()
    {
        player.playOnAwake = false;
        player.source = VideoSource.Url;
        player.url = Application.streamingAssetsPath + "/intro.mp4";
    }

    // 사용자가 재생 버튼을 눌렀을 때 호출합니다.
    public void PlayVideo()
    {
        player.Play();
    }
}

게임이 멈춰요

코드나 사용 중인 플러그인에 new Thread, ThreadPool, Task.Run, Parallel.For처럼 .NET 스레드로 작업을 실행하는 코드가 있는지 확인하세요. 이 가이드의 Unity 6·2022 LTS Web 빌드에서는 C# 멀티스레딩을 지원하지 않습니다. 네이티브 C/C++ 스레드 지원 옵션을 켜도 C# 스레드 코드를 그대로 사용할 수 있는 것은 아닙니다.

task.Wait(), task.Result, Thread.Sleep, 완료될 때까지 반복하는 while도 확인하세요. 메인 스레드에서 동기 대기하거나 오래 계산하면 화면 갱신이 멈출 수 있습니다. async·await 자체가 멀티스레딩을 뜻하지는 않으므로, 비동기 코드를 전부 지우기보다 작업을 실행하고 기다리는 방식을 확인하세요.

오래 걸리는 반복 처리는 코루틴으로 나누고 yield return null로 다음 프레임에 이어서 실행하세요. 아래는 Unity 2022 LTS와 Unity 6에서 사용할 수 있는 구조 예시입니다. 주석 위치에 실제 처리 코드를 넣고, 프레임마다 처리할 개수는 작업량에 맞춰 조정하세요. 

using System.Collections;
using UnityEngine;

// MonoBehaviour 안에 작성합니다.
// 시작할 때 StartCoroutine(ProcessInFrames());를 호출하세요.
private IEnumerator ProcessInFrames()
{
    for (int i = 0; i < 1000; i++)
    {
        // 여기에 한 항목을 처리하는 짧은 코드를 작성합니다.
        if ((i + 1) % 10 == 0)
            yield return null; // 다음 프레임까지 양보합니다.
    }
}

Unity 6에서는 Awaitable.NextFrameAsync()로 다음 프레임을 기다릴 수도 있습니다. Awaitable은 Unity 2022 LTS에 없는 API이므로 버전에 맞는 예시를 사용하세요. 

using UnityEngine;

// Unity 6의 MonoBehaviour 안에 작성합니다.
// 다른 async 메서드에서 await ProcessInFramesAsync();로 호출하세요.
private async Awaitable ProcessInFramesAsync()
{
    for (int i = 0; i < 1000; i++)
    {
        // 여기에 한 항목을 처리하는 짧은 코드를 작성합니다.
        if ((i + 1) % 10 == 0)
            await Awaitable.NextFrameAsync();
    }
}

두 예시는 메인 스레드의 작업을 여러 프레임에 나누는 방식이며, 병렬로 계산하지 않습니다. 한 항목의 처리 자체가 길면 그 작업도 더 작게 나눠야 합니다. Awaitable.BackgroundThreadAsync()는 백그라운드 스레드를 사용하므로 웹용 대안으로 쓰지 마세요.

다운로드는 UnityWebRequest.SendWebRequest(), 씬 로딩은 SceneManager.LoadSceneAsync()처럼 Unity가 제공하는 비동기 작업을 사용하고, 코루틴에서 yield return으로 완료를 기다리세요. 변경 후에는 실제 Web 빌드에서 멈췄던 구간을 다시 확인하세요. 스레드 코드가 없다면 브라우저 콘솔의 오류와 멈추기 직전 동작을 기록해 다른 원인도 확인하세요.

리듬 게임을 웹에 올리니 음악과 노트·판정이 어긋나요

음악 재생을 요청한 시점과 실제 재생 준비가 끝난 시점을 같은 것으로 처리하지 않았는지 확인하세요. 브라우저에서는 오디오 로딩·디코딩과 재생 허용 상태를 확인해야 합니다. 시작 후 몇 프레임을 기다리거나 일정 시간 뒤에 무조건 노트·판정을 시작하는 방식은 기기와 브라우저가 달라졌을 때 같은 출발점을 보장하지 않습니다.

  • 재생 준비: 채보와 오디오의 로딩 완료·실패를 확인한 뒤 시작하세요. AudioClip.loadState와 실제 재생 상태를 확인하고, 재생이 허용되지 않았거나 실패한 상태에서는 판정 시간만 진행하지 않도록 처리하세요.
  • 하나의 시간 기준: 음악은 PlayScheduled로 예약하고, 노트·판정·이동도 같은 시작 시각을 기준으로 계산하세요. PlayScheduled는 WebGL에서 지원되지만, 호출했다는 사실만으로 로딩 완료나 사용자가 듣는 소리와 판정의 일치까지 보장하지는 않습니다.
  • 재개 처리: 다른 탭으로 이동했다 돌아오거나 일시정지를 해제했을 때, 음악과 판정을 함께 멈추고 같은 곡 위치에서 재개하도록 구현하세요. Time.timeScale만 바꾸는 것으로 오디오와 별도로 계산한 DSP 시간까지 관리되지는 않습니다. 탭 복귀 후 곡 시간이 건너뛰어 노트가 한꺼번에 Miss 처리되지 않는지도 확인하세요.
  • 출력·입력 지연: 실제 Web 빌드에서 음악과 입력의 오차를 측정하고 보정값을 제공하세요. 에디터에서 맞춘 값 하나를 모든 브라우저·오디오 장치에 그대로 적용하지 마세요. 재생 중이라는 상태와 사용자의 귀에 소리가 도달한 시점도 구분해야 합니다.

첫 시작, 재시도, 곡 변경, 일시정지·재개, 탭 전환을 각각 확인하세요. 일정한 오차와 플레이할수록 커지는 오차를 구분해 원인을 찾고, 판정 범위만 넓혀 시간 기준의 불일치를 덮지 마세요.

좋지 않은 패턴 · 재생 요청과 동시에 별도 타이머 시작

using UnityEngine;

public class UncheckedSongTimer : MonoBehaviour
{
    [SerializeField] private AudioSource music;
    public float SongSeconds { get; private set; }

    private void Start()
    {
        music.Play(); // 로딩·재생 가능 여부를 확인하지 않습니다.
    }

    private void Update()
    {
        // 음악이 재생되지 않아도 노트·판정 시간은 진행됩니다.
        SongSeconds += Time.deltaTime;
    }
}

다음은 ScheduledSongTimer.cs로 저장하는 첫 재생용 예시입니다. Music에 AudioSource를 연결하고 Play On Awake를 끄세요. 클립의 Preload Audio Data를 켜고, 채보와 오디오 로딩이 끝난 뒤 시작 버튼에서 StartFromButton()을 호출하세요. 준비되지 않은 경우에는 시작을 거절합니다.

권장 패턴 · 준비 상태 확인 후 하나의 예약 시작 시각 사용

using System;
using UnityEngine;

public class ScheduledSongTimer : MonoBehaviour
{
    [SerializeField] private AudioSource music;
    private double scheduledStart;
    private bool hasSchedule;

    public void StartFromButton()
    {
        if (hasSchedule) return;
        if (music == null || music.clip == null ||
            music.clip.loadState != AudioDataLoadState.Loaded)
        {
            Debug.LogWarning("음악이 준비되지 않았습니다. 로딩 후 다시 시작하세요.");
            return;
        }

        music.Stop();
        music.playOnAwake = false;
        music.loop = false;
        music.pitch = 1f;
        music.time = 0f;
        scheduledStart = AudioSettings.dspTime + 0.25d;
        music.PlayScheduled(scheduledStart);
        hasSchedule = true;
    }

    public bool TryGetSongTime(out double seconds)
    {
        seconds = 0d;
        if (!hasSchedule || AudioSettings.dspTime < scheduledStart)
            return false; // 예약 시작 전에는 판정하지 않습니다.

        if (!music.isPlaying)
        {
            CancelSong(); // 재생 중이 아니면 판정도 진행하지 않습니다.
            return false;
        }

        seconds = Math.Max(0d, AudioSettings.dspTime - scheduledStart);
        return true;
    }

    public void CancelSong()
    {
        hasSchedule = false;
        if (music != null) music.Stop();
    }

    private void OnDisable() => CancelSong();
}

노트 배치·이동·판정은 모두 TryGetSongTime이 반환한 같은 곡 시간을 사용하고, 반환값이 false면 진행하지 않도록 연결하세요. 0.25초는 예약 준비를 위한 예시 여유 시간이며, 로딩 대기 시간이나 지연 보정값이 아닙니다. 이 예시는 첫 시작만 다룹니다. 일시정지·탭 복귀 시 재동기화와 출력·입력 지연 보정은 별도로 구현해야 합니다. isPlaying만으로 실제 소리가 출력됐는지까지 확인할 수는 없습니다.

JSON파일이 파싱이 안돼요

먼저 파일을 읽지 못한 것인지, 읽은 문자열을 데이터로 변환하지 못한 것인지 구분하세요. Web 빌드에서 StreamingAssets는 웹 주소이므로 File.ReadAllText로 읽을 수 없습니다. 고정 JSON은 TextAsset으로 포함하거나, UnityWebRequest로 다운로드를 완료한 뒤 파싱하세요. 서버에서 받은 값이 JSON 대신 오류 페이지나 로그인 화면의 HTML은 아닌지도 확인하세요.

문자열을 정상적으로 읽었다면 따옴표·쉼표·괄호와 필드 이름·자료형을 확인하세요. JsonUtility를 사용한다면 데이터 클래스에 [Serializable]을 붙이고 직렬화할 필드를 선언해야 합니다. 일반 프로퍼티와 Dictionary는 지원하지 않으며, 최상위 배열은 객체로 감싸야 합니다. 파싱 중 예외가 없더라도 필수 데이터가 채워졌는지 검증하세요.

좋지 않은 패턴 · 웹 주소를 로컬 파일 경로로 읽기

using System.IO;
using UnityEngine;

public class LocalJsonReader : MonoBehaviour
{
    private void Start()
    {
        string path = Path.Combine(Application.streamingAssetsPath, "data.json");
        // Web에서는 path가 URL이므로 이 방식으로 읽을 수 없습니다.
        string json = File.ReadAllText(path);
        Debug.Log(json);
    }
}

다음은 고정 JSON을 읽는 EmbeddedJsonReader.cs 예시입니다. Json File에 JSON 파일을 연결하세요. 예시 형식은 {"items":[{"id":"item-1","title":"예시 항목"}]}입니다. 최상위 객체의 items 필드 안에 배열을 넣습니다.

권장 패턴 · 빌드에 포함한 TextAsset을 파싱하고 검증

using System;
using UnityEngine;

public class EmbeddedJsonReader : MonoBehaviour
{
    [Serializable]
    public class Item
    {
        public string id;
        public string title;
    }

    [Serializable]
    public class Document
    {
        public Item[] items;
    }

    [SerializeField] private TextAsset jsonFile;
    public Document Data { get; private set; }
    public bool IsReady => Data != null;

    private void Awake()
    {
        try
        {
            if (jsonFile == null || string.IsNullOrWhiteSpace(jsonFile.text))
                throw new InvalidOperationException("내용이 있는 JSON 파일을 연결하세요.");

            Document parsed = JsonUtility.FromJson<Document>(jsonFile.text);
            if (parsed == null || parsed.items == null)
                throw new FormatException("items 배열이 필요합니다.");

            foreach (Item item in parsed.items)
            {
                if (item == null || string.IsNullOrWhiteSpace(item.id))
                    throw new FormatException("각 항목에는 id가 필요합니다.");
            }

            Data = parsed; // 필수 데이터 검증까지 성공한 경우에만 사용합니다.
        }
        catch (Exception error)
        {
            Data = null;
            Debug.LogError("JSON 로딩·파싱 실패: " + error.Message, this);
        }
    }
}

이 예시에서는 빈 items 배열도 정상 데이터로 허용합니다. 항목 수·숫자 범위·중복 ID 등 추가 조건은 실제 데이터 규칙에 맞춰 검증하세요. 데이터를 사용하는 쪽에서는 IsReady를 확인하고, 실패 시 오류를 화면에도 표시하세요. 외부 JSON도 다운로드 성공을 확인한 뒤 같은 파싱·검증 절차를 적용하면 됩니다.

참고: Unity JSON 직렬화 ↗ · Unity StreamingAssets의 Web 접근 방법 ↗

키보드는 되는데 전용 컨트롤러가 웹에서 안 먹어요

장치 이름에 특정 문자열이 들어간 경우만 입력을 받거나, PC에서 쓰던 장치 레이아웃·버튼 번호를 그대로 가정하는지 확인하세요. 브라우저의 Gamepad API는 운영체제의 입력 장치를 그대로 노출하지 않으며, 장치 식별 문자열의 형식과 지원 여부도 브라우저·운영체제에 따라 달라집니다. 연결된 장치가 코드의 이름 검사에서 제외되면 버튼을 눌러도 판정에 전달되지 않습니다.

실제 Web 빌드에서 감지된 장치와 각 버튼 입력을 먼저 표시해 확인하세요. 특정 이름만 허용하기보다 입력 액션과 사용자 재설정으로 연결하고, 표준 매핑이 없는 장치에는 별도 매핑이나 키보드 대체 조작을 제공하세요. 게임 화면에 포커스를 둔 상태에서 컨트롤러 버튼을 누른 뒤 감지되는지도 확인해야 합니다. PC에서 인식됐다는 사실만으로 웹에서도 지원된다고 판단하지 마세요.

좋지 않은 패턴 · PC에서 확인한 장치 이름만 허용

using UnityEngine;
using UnityEngine.InputSystem;

public class NamedPadOnly : MonoBehaviour
{
    private void Update()
    {
        var pad = Gamepad.current;
        if (pad == null || pad.displayName != "My Rhythm Controller")
            return; // 다른 이름으로 노출되면 입력을 전부 버립니다.

        if (pad.buttonSouth.wasPressedThisFrame)
            Debug.Log("판정 입력");
    }
}

다음은 Input System 패키지를 사용하는 ActionBasedHitInput.cs 예시입니다. Active Input Handling에서 Input System을 활성화하고, On Hit에 게임의 판정 함수를 연결하세요. 장치 이름 대신 표준 게임패드 버튼과 키보드를 같은 액션에 연결합니다.

권장 패턴 · 이름 검사 없이 입력 액션과 대체 조작 제공

using UnityEngine;
using UnityEngine.Events;
using UnityEngine.InputSystem;

public class ActionBasedHitInput : MonoBehaviour
{
    [SerializeField] private UnityEvent onHit = new UnityEvent();
    private InputAction hit;

    private void Awake()
    {
        hit = new InputAction("Hit", InputActionType.Button);
        hit.AddBinding("<Keyboard>/space");
        hit.AddBinding("<Gamepad>/buttonSouth");
    }

    private void OnEnable() => hit.Enable();
    private void OnDisable() => hit.Disable();
    private void OnDestroy() => hit.Dispose();

    private void Update()
    {
        if (hit.WasPressedThisFrame())
            onHit.Invoke();
    }
}

이 예시의 buttonSouth는 표준 매핑 게임패드용이며, 모든 전용 컨트롤러를 지원한다는 뜻은 아닙니다. 브라우저에서 장치가 어떤 레이아웃·컨트롤로 감지되는지 확인한 뒤 필요한 바인딩과 사용자 재설정을 추가하세요. 브라우저가 노출하지 않는 장치는 바인딩을 바꾸는 것만으로 사용할 수 없습니다. 판정 함수에서도 게임 시작·일시정지 상태를 확인하세요. 이 예시는 입력 연결용이며 정밀한 리듬 판정의 입력 시각 보정까지 다루지는 않습니다.

웹을 따로 지원하기 귀찮아요

프로젝트를 따로 만들기보다, 플랫폼마다 달라야 하는 코드만 #if·#else·#endif 전처리기로 나눠보세요. Unity가 제공하는 UNITY_WEBGL 심볼로 Web 빌드에 포함할 코드를 선택할 수 있습니다.

아래는 메서드 안에서 코드를 나누는 구조 예시입니다. 주석 위치에 각 플랫폼에서 사용할 코드를 작성하세요.

#if UNITY_WEBGL && !UNITY_EDITOR
    // 실제 Web 빌드: 웹에서 지원하는 방식으로 파일·영상을 불러옵니다.
#else
    // 에디터 및 다른 플랫폼: 기존에 사용하던 코드를 실행합니다.
#endif

!UNITY_EDITOR는 에디터 실행을 제외하는 조건입니다. Web을 빌드 대상으로 선택한 에디터에서도 웹용 분기를 사용하려면 #if UNITY_WEBGL만 쓰세요. 실제 브라우저에서의 동작은 빌드·업로드 후 확인해야 합니다.

전처리기는 조건에 맞는 코드만 컴파일에 포함합니다. 지원되지 않는 기능을 자동으로 바꿔주지는 않습니다. 웹에서 사용할 수 없는 API·플러그인의 호출이나 using 선언도 필요한 범위에서 함께 분리하고, 웹용 분기에는 대체 코드를 작성하거나 해당 기능을 생략하세요.

외부 API·멀티플레이 연결 신청

내 작품 → 외부 연결에서 호스트명과 HTTPS/WSS 방식을 선택해 신청합니다. 새 신청은 모든 포트가 기본이며 특정 포트는 고급 설정에서 지정합니다. 하위 도메인 범위는 루트 호스트를 포함하지 않습니다. URL의 숫자 포트는 설정과 일치해야 하며 경로·쿼리·자격 증명은 허용하지 않습니다.

기존 사용 목적·서버 설정 계획에 SDK/버전·게임 모드, 목적지별 용도, 인증 방식(비밀정보 제외), 외부 서비스 운영 담당자와 2인 플레이 확인 절차를 적으세요. CORS·Origin 검사·인증은 외부 서비스 담당자가 설정해야 합니다.

신청 → 관리자 승인 → 새 실행 순서로 진행합니다. 기존 승인과 겹치면 철회 후 새 승인이 필요하며 기존 플레이의 이후 파일 요청·갱신이 거절됩니다. 승인 후 서로 다른 두 계정으로 같은 방에 접속해 양방향 게임 상태와 재접속을 확인하세요. 서비스 예시는 Photon/Relay 연동 보장이 아닙니다.

현재 마감 후에는 새 연결 신청이 제한되며, 실행 중 API 갱신이 실패하면 게임이 종료됩니다. 마감 후 권한과 일시적 실패 재시도는 후속 개선 항목입니다.
