----------------

origin/master: 29e360d3152d505d0ae2d7f1e39ca950fcea0df8
git ls-remote로 원격 master와 같은 SHA임을 확인했다.

사용자 본문에는 호스팅 판단을 떠넘기지 않고, 목적별 설정과 실제 게임 확인 절차를 안내한다.

1. Brotli/Gzip + Fallback OFF를 새 빌드의 기본 안내로 정한 이유
-----------------------------------------------------------
archive.ts: .framework.js/.wasm/.data의 비압축, .gz, .br, .unityweb 조합을 인식한다.
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/api/src/modules/webgl/archive.ts

content.ts: .gz에는 gzip, .br에는 br Content-Encoding을 정한다.
접미사를 제외한 이름으로 MIME을 정하므로 .wasm.br/.wasm.gz의 MIME은 application/wasm이다.
.unityweb은 application/octet-stream이며 HTTP Content-Encoding을 붙이지 않는다.
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/api/src/modules/webgl/content.ts

processing.composition.ts: 저장소 업로드에 contentType/contentEncoding을 전달한다.
project-publication/worker.ts: 게시 대상 업로드에도 mimeType/contentEncoding을 전달한다.
lib/storage.ts: S3 업로드의 ContentType/ContentEncoding에 반영한다.
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/api/src/modules/webgl/processing.composition.ts
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/api/src/modules/project-publication/worker.ts
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/api/src/lib/storage.ts

public-origin.nginx.conf.template: gzip off; 저장소의 MIME/Content-Encoding을 통과시킨다.
일반 파일 및 /runtime/ 경로에서 Content-Encoding을 제거하거나 재압축하지 않는다.
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/db/public-origin.nginx.conf.template

따라서 사용자에게 서버 설정을 확인하라고 요구할 이유 없이,
새 공개용은 Brotli + OFF, 빠른 반복은 Gzip + OFF로 안내한다.
이는 필수 업로드 포맷을 뜻하지 않는다. 비압축·Fallback ON의 경로도 존재한다.
ZIP 안전성 제한과 실제 게임 호환성은 별도의 조건이다.
압축 포맷 사이에 동일 게임의 FPS 우열을 실측했다고 주장하지 않는다.

2. Profiler 연결과 Deep Profiling
--------------------------------
Unity의 Web Profiler는 플레이어가 에디터에 연결하는 방식이다.
Autoconnect Profiler는 업로드 성공 또는 FPS 표시를 위한 필수 옵션이 아니다.
runtimeCsp는 실행 경로와 승인된 외부 연결만 connect-src에 포함한다.
업로드했다고 임의의 개발 PC Profiler 연결이 열리는 구조가 아니다.
https://github.com/pcugame/pcugame.github.io-infra/blob/29e360d3152d505d0ae2d7f1e39ca950fcea0df8/apps/api/src/modules/webgl-play/service.ts

그래서 일반 업로드 플레이/FPS 확인은 Development/Deep Profiling OFF,
문제 분석용 Development ON, 함수 단위 추가 분석 때만 Deep Profiling ON으로 구분한다.
진단용 빌드를 업로드할 수 있다는 것과 원격 Profiler 연결 성공은 별개다.
연결 정책을 바꾸라는 안내는 하지 않는다.

3. 네이티브 스레드·템플릿·데이터 캐시
-----------------------------------
기준 gateway 설정에는 COOP same-origin, COEP require-corp, CORP cross-origin이 있다.
runtimeCsp의 worker-src에는 runtime 경로와 blob:가 허용된다.
따라서 스레드 옵션을 설명하면서 사용자에게 헤더 설정을 요구하지 않는다.
Unity 6.0 실험적 옵션이므로 기본 OFF, 효과를 측정할 이유가 있을 때만 비교하도록 안내한다.
특정 게임의 성능 이득, 모든 스레드 빌드의 실행 성공은 이 조사에서 검증하지 않았다.

기준 master의 gateway는 Service Worker 등록 요청을 차단한다.
PWA 오프라인·설치 기능을 안내용 기본 경로로 제시하지 않고 Default 템플릿을 추천한다.
Data Caching은 Unity 데이터 캐시다. PWA 지원이나 재방문마다 동일 캐시 적중을 뜻하지 않는다.
실행 URL에 세션 토큰이 포함되고 브라우저 저장 조건도 달라질 수 있어 효과를 보장하지 않는다.
