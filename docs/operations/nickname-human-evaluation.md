# 닉네임 행동 피드백과 Preference 데이터

`/lab/nickname-evaluation`에서 벤치마크 정답 여부와 모델 행동을 독립적으로 검수하고, 승인한 원본 응답을 unpaired preference JSONL로 생성한다. 교정된 모범 응답을 작성하는 단계는 없다. GPU 학습 알고리즘은 이번 변경의 범위에 포함하지 않는다.

## 평가 기준

벤치마크 정답 여부는 `correct`·`partial`·`incorrect`·`deferred`, 행동 피드백은 `positive`·`negative`·`exclude`이다. 기본 행동 피드백은 `exclude`이며 정답 여부를 바꾸어도 자동 변경되지 않는다.

| 사례 | 벤치마크 | 행동 피드백 |
| --- | --- | --- |
| 은어를 알지 못하여 정직하게 판단 유보 | 오답 | 학습 제외 |
| 평범한 인물명을 정치적 논란만으로 위험 판정 | 오답 | 부정 |
| 기대 점수와 일치하나 판단 근거를 생성 | 부분 정답·오답 | 부정 |
| 제공 자료를 정확히 해석하고 근거에 비례하여 판단 | 정답 | 긍정 |

특정 인물명의 화이트리스트는 사용하지 않는다. 주제·인물·사상·커뮤니티의 논란과 닉네임에 실제 존재하는 모욕·비하 의미를 구분한다. 검색 발췌문에서 근거를 발견하지 못한 사실은 인터넷 전체에 정보가 없다는 뜻이 아니다. 검색 없는 실행에서 일반 지식을 사용하였다는 사실만으로 환각으로 분류하지 않는다.

부정 사유는 근거 없는 사실 생성, 제공 자료와 모순되는 주장, 출처 왜곡, 과도한 위험 판단, 주제 또는 인물 자체에 대한 부당한 위험 판단, 미검증 가설의 단정, 부적절한 불확실성 처리, 모델 귀속 출력 계약 위반의 8개 유형이다. 은어 지식 부족, 난독화 복원 실패, 기대 점수 차이와 낮은 BERTScore만으로 부정 피드백을 지정하지 않는다.

## 실험 설정과 재실행

공통·검색·답변 지침을 직접 편집하거나 UTF-8 JSON 파일로 가져오기·내보내기할 수 있다. 공백·줄바꿈·빈 문자열을 포함한 사용자 원문을 보존한다. 실제 모델 지침은 공통 지침과 해당 단계 지침을 결합하며, 재생성 시 보정 지침을 추가한다. 각 생성 단계에는 실제 지침·입력, 제공 자료, 원본 생성 응답, 종료 사유와 프로그램 검증 결과를 기록한다. 연구 실행 이력에는 검색 질의, 자료 수집 시각, 모델 가중치·chat template 식별값, 토큰·생성 설정이 포함된다.

지침 편집으로 JSON schema, 닉네임·출처 ID·인용문 검증, 검색·생성 횟수, 토큰·시간 예산을 변경할 수 없다. 기계적으로 검증 가능한 위반에는 constrained decoding과 Worker 검증을 우선 적용한다.

저장된 실험을 선택한 뒤 **선택한 실험 설정 복사**를 사용한다. 데이터셋·사례 순서·모델·검색 모드·생성 설정을 고정한 상태로 재실행하거나 프롬프트만 수정할 수 있다. 원본 실험은 유지하고 새 실행을 생성하여 `replayOf`를 기록한다. 원본에 가중치·chat template hash가 있으면 Worker가 일치를 검사하며, 다른 revision이면 생성을 중단한다. 해당 식별값이 없는 과거 실행은 모델 이름·provider까지만 고정된다. 검색은 다시 수행하므로 같은 설정이라도 검색 자료와 응답은 달라질 수 있다.

**행동 평가 정책 원문**은 실행별 검수 정책이다. 모델 입력에 자동 추가하지 않으며, 프롬프트와 별도로 저장한다. 기존 실행에는 정책을 소급 지정하지 않는다.

## 연속 검수

1. 원본 닉네임, 모델 점수·근거, 모델에 실제 제공한 발췌문을 확인한다.
2. 필요하면 **기대 정답 공개**로 기대 근거와 점수를 확인한다.
3. 벤치마크 정답 여부와 행동 피드백을 각각 선택한다.
4. 부정 피드백이면 사유를 하나 이상 선택한다.
5. **저장 후 다음**으로 이동한다.

키보드에서는 `1`–`4`로 정답 여부, `A`·`S`·`D`로 긍정·부정·학습 제외를 선택한다. 사유는 `Tab`·`Space`, 저장 후 이동은 `Ctrl+Enter` 또는 `Cmd+Enter`를 사용한다. 저장되지 않은 편집이 없을 때 `J`·`K`로 이동한다. 입력란에서 문자를 입력하는 동안 단축키는 작동하지 않는다.

검색 이력, 토큰, 출처 검증, 원본 응답과 프로그램 처리 결과는 상세 영역에 보존한다. 메모·출처 지지 여부·사례 유형은 선택 사항이며 학습을 위한 교정 JSON 입력은 요구하지 않는다. 검수는 결과 hash와 직전 검수 ID를 비교하여 저장하며, BERTScore의 후속 계산은 검수 hash에 영향을 주지 않는다.

## 일괄 승인과 내보내기

**행동 피드백 · Preference 데이터**에서 현재 실험의 평가 정책·프롬프트 범위를 명시적으로 선택한다. 학습 가능한 피드백을 선별하고 **선택한 피드백 일괄 승인**을 실행한다. 승인된 선택은 별도 반복 확인 없이 JSONL로 다운로드한다. 승인 요청 전체를 한 transaction으로 검증하며, 오래된 검수나 학습 불가 사례가 포함되면 일부만 승인하지 않는다.

파일은 현재 실험 범위로 한정한다. 서로 다른 평가 정책·프롬프트의 실행은 별도 파일로 관리한다. 화면과 manifest에 긍정·부정 수, 부정 사유, 표현군 분포, 프롬프트 hash와 평가 정책을 표시한다.

| 선별 조건 | 기본값 |
| --- | --- |
| 표현군별 최대 건수 | 3 |
| 표현군·사유별 최대 건수 | 1 |
| 한 표현군의 최대 비중 | 50% |
| 긍정 피드백 최소 비중 | 20%, 설정 하한 10% |

긍정 사례는 벤치마크 정답과 별개로 행동의 적절성을 검수하여 선택한다. 부정 사례에 편중된 데이터로 판단 회피를 유도하지 않도록 최소 비중을 적용한다.

표현군은 기존 NFKC·공백·대소문자 정규화와 고정 분할을 유지한다. 동일 닉네임·표현군의 train/validation/test 충돌을 데이터셋 등록과 승인·내보내기에서 거부한다. train만 학습 파일에 포함하며 validation/test는 원본 reference와 검수 이력을 포함한 평가 전용 파일로 내보낸다. 최종 test 실행에는 기존 설정 확정 조건을 적용한다.

## 원본 응답과 파일 계약

학습 파일 `nickname-preference-<id>.jsonl`의 각 행은 다음 세 필드만 포함한다.

```json
{"prompt":[{"role":"system","content":"당시 실제 지침"},{"role":"user","content":"당시 닉네임 및 자료"}],"completion":[{"role":"assistant","content":"실제 생성 원문"}],"label":false}
```

긍정은 `label=true`, 부정은 `label=false`이다. 학습 제외는 파일에 포함하지 않는다. 최종 판단 단계만 선택하며 검색 action 학습은 제공하지 않는다. 모델이 실제 생성한 잘못된 JSON도 원문으로 보존한다. PostgreSQL에 저장할 때 원문을 JSON 문자열로 한 번 인코딩하고 내보낼 때 디코딩하므로 NUL·잘못된 Unicode·공백·줄바꿈을 복원할 수 있다. 파싱한 결과를 원본 생성 응답 대신 직렬화하지 않는다.

다음 사례는 행동 피드백을 기록할 수 있으나 학습 파일에서 제외한다.

- 원본 응답·정확한 입력·종료 상태가 남아 있지 않은 실행: 재실행 필요
- 네트워크·검색 서비스·GPU·Worker 장애와 미완료 실행
- 출력 길이 제한 등으로 잘린 최종 응답
- 과거 SFT 검수·후보, 평가 정책이 없는 과거 실행
- validation/test, 표현군 미지정, 결과 변경 후 재검수하지 않은 사례

모델 귀속 계약 위반 사유는 최종 생성 단계에 프로그램의 검증 실패가 기록되어 있어야 승인할 수 있다. 실패한 마지막 시도 대신 이전 성공 응답을 선택하지 않는다.

기대 점수·기대 근거·BERTScore·오류 분류·사용자 ID는 학습 입력에 포함하지 않는다. 별도 `nickname-provenance-<id>.json`에는 데이터셋·모델·평가 정책·프롬프트 식별정보, 원본 결과, 검수·승인 이력과 파일 SHA-256을 보존한다. 검수 변경은 기존 승인을 무효화하며, 이미 생성된 파일은 당시 내용으로 다시 다운로드할 수 있다.

## 과거 기록과 오프라인 준비

기존 `human-curation-v1` 후보·교정 응답·내보내기는 연구 이력으로 조회·다운로드할 수 있다. 신규 SFT 후보 생성과 교정 UI·API는 제거하였다. 과거 정답·오답을 신규 preference label로 자동 변환하지 않는다.

`experiments/nickname-lora/cli.mts prepare`는 신규 preference export의 파일 hash·원본 응답·검수·승인·정책·분할을 재검증하고 `preference.jsonl`과 `nickname-preference-v1` manifest를 생성한다. label을 제거하거나 SFT `train.jsonl`로 변환하지 않는다. 기존 GPU SFT/LoRA 알고리즘과 합성 smoke 기능은 그대로이며, 신규 preference manifest는 기존 trainer의 입력 계약에서 거부된다. Preference 학습 알고리즘의 도입과 학습 효과 평가는 후속 단계이다.

## Migration과 검증

`20261125200000_lab_preference_feedback`은 `LabRun.feedbackPolicy`, `replayOf`, `replayIdentity`를 nullable 열로 추가하는 transaction migration이다. 기존 결과·검수·후보·파일을 변경하거나 삭제하지 않는다. API·Worker·Web 갱신 전에 적용하며, 운영 적용은 기존 배포 절차를 따른다.

공유 계약 테스트는 독립 평가, 원문·잘못된 JSON 보존, 잘림·장애 제외, 정책·표현군·긍정 비중을 검사한다. PostgreSQL 테스트는 실제 인증·직렬화, 빈/채워진 응답, 승인 원자성·재요청·충돌, 소유권과 내보내기를 검사한다.

```sh
npm test -w @pcu/contracts
npm run test:integration:suite -- nickname-evaluation
node --import tsx --test experiments/nickname-lora/pipeline.test.mts
# DATABASE_URL은 로컬 검증 DB, Playwright·Chromium 경로는 설치 환경에 지정한다.
node --import tsx apps/web/src/__tests__/helpers/lab-preference.browser.mjs
```

브라우저 검증은 실제 Web·Fastify API·격리 PostgreSQL·benchmark Worker를 사용한다. 모델·검색 HTTP 응답만 결정적인 fixture로 제공한다. 데이터셋 등록, 사용자 프롬프트, 키보드 검수, 잘못된 JSON의 부정 피드백, 일괄 승인, 원문 일치 다운로드, 새로고침 보존, 설정 복사와 1440/390/320px 배치를 확인한다. 실제 모델의 판단 품질과 GPU 학습 효과에 대한 측정은 포함하지 않는다.
