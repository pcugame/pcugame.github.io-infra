# 닉네임 Human Evaluation과 학습 데이터 선별

`/lab/nickname-evaluation`의 실험 결과에서 모델 응답을 검수하고, 승인한 대표 사례를 학습용 JSONL로 생성한다. 원본 결과, 사람의 검수, 교정 후보, 승인과 파일 생성 이력을 별도로 보존한다. 가중치 학습은 수행하지 않는다.

## 검수 절차

1. **한 사례씩 검수**에서 닉네임, 해석 후보, 실제 검색 질의, 수집 출처, 모델 근거와 점수를 확인한다. 기본 화면은 기대 정답을 숨긴다. **검수 저장** 후 **기대 정답 공개**를 선택하면 최초 판단을 정답 확인 전 검수로 보존할 수 있다.
2. 정답·부분 정답·오답·평가 보류를 선택한다. 부분 정답과 오답은 오류 유형을 복수 지정하고, 검색·프롬프트·평가 정책·모델 능력·실행 장애·기대 정답 중 문제 영역을 기록한다.
3. 정상·문제·모호 사례 유형, 근거 적합성, 해석 성공 여부, 인용 출처별 관련성과 주장 지지 여부를 평가한다. 미평가 항목은 `null`로 유지한다.
4. 필요한 응답 필드만 교정한다. **기대 근거·점수로 교정 초안 채우기**는 원래 데이터셋의 기대 근거와 점수를 재사용한다. 원본 결과와 데이터셋은 변경하지 않는다. 검색 행동은 action JSON으로, 연구 응답의 인용문과 해석 상태는 별도 JSON으로 교정한다.
5. 검수 저장 후 A/B/C 학습 목표와 해당 생성 단계를 선택하여 후보를 생성한다. 후보의 실제 입력과 교정 응답을 확인하고, 근거 범위와 표현군 확인 항목에 동의한 뒤 개별 승인한다.
6. 표현군·오류 유형별 후보 목록에서 대표 사례를 선택한다. 정상·모호 사례의 정답과 근거에 충실한 정답을 포함하고, 구성 비율을 확인한 뒤 새 파일 생성을 승인한다.

키보드에서 `1`~`4`는 평가 상태를 선택한다. `J`·`K`는 다음·이전 사례로 이동하고, `Ctrl+Enter`는 저장 후 다음 사례로 이동한다. 입력란의 일반 문자 입력은 단축키로 처리하지 않는다. 저장하지 않은 수정이 있으면 사례 이동과 결과 필터 변경을 제한한다. 저장 오류는 화면에 유지하며 다음 사례로 이동하지 않는다.

검수 시점의 결과 hash와 이전 검수 ID를 서버에서 비교한다. 동시에 수정한 검수는 덮어쓰지 않으며, 재실행이나 새 검수로 기준이 변경된 후보는 승인·내보내기에서 제외한다. 기존 승인과 생성 파일은 이력으로 보존한다.

## 학습 목표와 근거 범위

| 목표 | 입력과 학습 대상 | 생성 조건 |
| --- | --- | --- |
| A · 표현 해석·검색 행동 | 기록된 action 입력 또는 닉네임만 포함한 최초 입력 → 해석 가설과 `search`·`finish` action | 교정 검색 질의 또는 유효한 기존 action 필요 |
| B · 근거 판단 | 기록된 최종 판단 입력과 실제 제공 발췌문 → 교정 판단 | 실제 제공 자료가 있는 생성 단계 필요 |
| C · 응답 구조 | 기록된 최종 판단 입력 → 검증된 JSON | 정확한 생성 입력 기록 필요 |

수집 자료 전체와 모델에 실제 제공한 자료는 다를 수 있다. B/C는 해당 생성 단계의 입력을 사용한다. 문맥 한도 때문에 잘리거나 제외된 자료를 교정 응답의 근거로 추가하지 않는다. 연구 응답의 출처 ID·인용문·해석 상태·점수·판단 유보를 다시 검증하며, 응답 본문에는 URL 대신 제공된 출처 ID를 사용한다. 기대 근거를 모델 입력에 추가하거나 기대 출처 URL로 검색 결과를 대체하지 않는다.

출처의 의미적 관련성과 교정 내용의 사실성은 자동으로 확정하지 않는다. 후보 승인 시 사람이 제공 자료 밖의 사실을 정답으로 강요하지 않았는지 확인한다. 기대 근거 재사용 여부와 확인 내역은 승인 이력에 기록한다.

검색 서비스·네트워크·Worker 장애, 알 수 없는 실행 실패, 기대 정답의 문제, 원인 미분류와 평가 보류는 학습 후보에서 제외한다. JSON·action 위반은 모델 오류로 검수할 수 있다. 검색 결과가 없는 경우 B 후보를 생성하지 않으며, 새로운 검색 행동은 A 후보로 교정한다. 존재하지 않는 검색 결과는 생성하지 않는다.

신규 Worker 실행은 검색 질의·결과·시간, 생성 입력·응답·시간을 기록한다. 이전 결과 중 정확한 생성 입력이 없는 사례는 B/C 후보 생성을 거부한다. 해당 사례는 재실행하거나 닉네임 입력에 대한 A 후보로 검수한다. 이전 기록에 없는 자료나 시간을 추정하여 채우지 않는다.

## 표현군 분할과 대표성

학습 선별에는 `familyId`가 필요하다. 동일 원형의 비속어·은어·난독화 변형에 같은 ID를 부여한다. 표기 정규화는 NFKC, 앞뒤 공백 제거, 연속 공백 축약, 소문자 변환으로 구성한다. 의미가 같은 서로 다른 family ID를 자동으로 판별하는 사전은 없으며, 승인자가 표현군 정합성을 확인한다.

가져온 명시적 split을 우선하고, split이 없는 표현군에는 고정 hash의 10개 구간 중 train 8개·validation 1개·test 1개를 배정한다. 이는 표현군 기준 배정이며 행 비율을 정확히 80/10/10으로 맞추는 방식은 아니다. 사용자별 난수나 조정 가능한 seed는 사용하지 않는다.

`LabFamilySplit`에 분할을 고정하여 사용자·데이터셋 판본이 달라도 같은 표현군이 서로 다른 split에 포함되지 않도록 한다. 기존 등록 자료의 표현군 충돌, 고정 split 변경, 동일 닉네임을 다른 표현군으로 재등록하는 경우를 거부한다. 기존 충돌 자료는 삭제·재배정으로 우회하지 않으며 데이터 관리자가 원형과 split을 정합해야 한다. 표현군이 없는 사례는 검수할 수 있으나 학습·평가 선별 파일에는 포함하지 않는다.

validation/test는 후보 생성 단계부터 제외한다. test를 포함한 벤치마크 실행은 설정 확정을 나타내는 `finalTest=true`를 명시해야 한다. 최종 test는 반복 튜닝에 사용하지 않고, 수정과 설정 선택에는 train·validation을 사용한다. 내보내기 서비스는 train 학습 메시지와 validation/test 평가 자료를 별도 파일로 생성한다.

기본 선별 조건은 다음과 같다. 모든 조건은 서버에서 다시 검증하며 적용한 값을 생성 이력에 보존한다.

| 조건 | 기본값 |
| --- | --- |
| 동일 표현군 최대 건수 | 3건, 설정 상한 10건 |
| 동일 표현군·오류 유형 최대 건수 | 1건, 설정 상한 3건 |
| 표현군별 최대 비중 | 50% |
| 교정 없이 보존하는 정답 최소 비중 | 20%, 설정 하한 10% |
| 정상 닉네임 정답 최소 비중 | 10% |
| 모호 닉네임 정답 최소 비중 | 10% |

한 사례에서 여러 목표의 후보를 만들 수 있으나 동일 파일에는 하나만 선택한다. 미승인 후보, 재검수가 필요한 후보, 평가 전용 split은 포함할 수 없다. 오류 사례 전체를 자동으로 선택하거나 승인하지 않는다.

## 지표와 분모

전체 사례 수, 최신 검수 수, 재검수 필요 수, 실패·취소·미완료·실행 장애 수와 사례 유형 미분류 수를 함께 제공한다. 지표별로 값·분자·분모·미측정 수를 표시한다. 위험 판정 임계점의 기본값은 50점이며 화면에서 변경할 수 있다.

| 지표 | 분모와 해석 |
| --- | --- |
| 근거 적합률·해석 성공률 | 전체 사례 수. 미검수는 성공으로 계산하지 않음 |
| 점수 MAE·평균 점수 | 유효 점수가 있는 성공 응답 수. 유보·실패·미채점 수 별도 표시 |
| 기대 점수 범위 충족률 | 전체 사례 수. 범위가 없으면 기대 점수와 정확히 일치해야 충족 |
| 정상 오탐률·문제 미탐률 | 사람이 분류한 정상·문제 사례 수. 대상 미채점률과 유형 미분류 수 병기 |
| 인용 출처 관련성·지지율 | 모델이 인용한 출처 ID 수. 미검수 출처 수 병기 |
| 판단 유보율 | 전체 사례 수. 점수 null도 유보로 집계 |
| 판단 유보·실패·미완료 비율 | 전체 사례 수. 유효 점수가 없는 모든 사례 포함 |
| JSON 유효 응답률 | 전체 사례 수. 취소·실패·미완료를 성공으로 계산하지 않음 |
| 높은 위험 점수 부여율 | 전체 사례 수. 평균 점수·오탐률과 함께 해석 |
| 검색·생성 시간 | 해당 시간 기록이 있는 사례 수. 기록 없는 이전 실행은 미측정 |

MAE가 낮더라도 유보·실패 비율이 높으면 전체 성능이 우수하다고 판단할 수 없다. 오탐·미탐률은 사람의 유형 분류와 미채점 비율에 영향을 받으므로 두 비율만으로 모델을 비교하지 않는다. 평균 위험 점수는 정확도 지표가 아니다.

## 파일과 감사 이력

`nickname-train-<id>.jsonl`은 각 행에 `messages`만 포함한다. system/user 입력과 assistant 학습 응답으로 구성하며 최종 응답과 action은 JSON 문자열이다. 모델 학습 도구의 chat template와 토큰화 설정은 다음 학습 단계에서 선택한다.

`nickname-validation-<id>.jsonl`과 `nickname-test-<id>.jsonl`은 `purpose=evaluation_only`, 원본 case/reference, 실행 결과와 검수를 포함한다. 학습 메시지는 생성하지 않는다.

각 파일과 함께 생성하는 `nickname-provenance-<id>.json`에는 데이터셋·프롬프트 hash, 모델·평가 지침, 표현군 분할, 선별 정책, 파일 hash, 원본 결과, 정확한 검수 판본, 후보와 승인자·승인 시각을 보존한다. 생성된 파일은 DB에 저장하며 생성 이력에서 동일 내용으로 다시 다운로드할 수 있다. 기존 파일을 새 검수로 덮어쓰지 않는다. Mock 모드의 파일명과 이력에는 모의 자료임을 표시한다.

Lab 접근은 기존 BETA_TESTER·ADMIN 권한과 소유자 범위를 유지한다. 검수와 후보·파일 생성 API에는 세션·CSRF·입력 계약과 속도 제한을 적용한다.

## Migration과 검증

`20261125120000_lab_human_evaluation`은 `LabHumanReview`, `LabTrainingCandidate`, `LabFamilySplit`, `LabCurationExport`와 `LabRun.finalTest`를 추가하는 transaction migration이다. 기존 데이터셋·결과·이력은 수정하지 않는다. 신규 저장 구조를 사용하기 전에 migration과 API를 적용하고 Worker·Web을 갱신한다. 이 변경에는 외부 객체 저장소 참조의 제거가 없다. 운영 적용과 복구는 [배포 절차](deployment.md)를 따른다.

공유 계약 테스트는 출처 범위, 표현군 분할, 대표성 제한, 지표 분모를 검증한다. `lab-human.postgres.test.ts`는 실제 migration과 인증된 API의 빈·채워진 응답, 승인 누락, 원본 보존, 검수 변경, 소유권, train/test 내보내기를 검증한다. 기존 독립 Worker suite와 함께 `nickname-evaluation` 통합 suite에 포함된다.

```sh
npm run test:integration:suite -- nickname-evaluation
npm test -w @pcu/contracts
npm test -w apps/web -- --run src/__tests__/humanReview.test.tsx src/__tests__/mockLabHuman.test.ts
# 기존 Playwright와 Chromium 설치 사용 가능
node apps/web/src/__tests__/helpers/lab-human.browser.mjs
```

브라우저 검증은 합성 Mock 응답으로 검수·승인·다운로드·새로고침 보존·모바일 배치를 확인한다. 실제 모델의 판단 품질이나 학습 효과에 대한 측정은 별도 단계이다.
