# Phase 2 통합 범위와 전환 조건

## 통합 범위

PR #49의 기준은 `master`의 `d103504`이다. 기존 작업 보존 커밋 `d90be24`를 유지하고 현재 `master`를 병합하여, 이미 운영에 반영된 수정과 Phase 2 전환을 구분한다.

| 구분 | 통합 결정 |
| --- | --- |
| 자료 첨부·영상 순서 | master에 이미 반영된 확장 마이그레이션을 보존한다. 동일 SQL을 추가하거나 수정하지 않는다. |
| canonical 자산 처리 | Phase 2의 단일 자산 표현, 보호된 업로드 준비 영역, DRAFT 제출 및 게시 워커를 적용한다. 호환되지 않는 legacy 업로드·전달 경로와 전용 스크립트를 제거한다. |
| 운영 수정 | 관측 지표 초기화 잠금, 보호 다운로드 서명, WebGL 참조 검증, 업로드 실패 후 재시도, 의존성 업데이트를 보존한다. |
| 릴리스 제어 | master 기준 CD, 불변 이미지·소스 검증, 권한·환경변수 전달, Pages 접근 제어, 전환·복구 절차를 유지한다. 임시 Prisma 설정의 외부 모듈 의존성을 제거한 기존 수정도 보존한다. |
| 이미지 구성 | 기존 contract SQL과 게시 워커를 포함하는 Phase 2 아티팩트를 빌드한다. 서버 시작 시 DB 마이그레이션을 실행하지 않는다. |
| 범위 제외 | 중복된 별도 Phase 1 자료 업데이트 스크립트는 통합 결과에서 제외한다. 원본은 `d90be24`에 보존한다. 수정·삭제 승인 기능은 #50에서 별도 검토한다. |

Phase 1에서만 허용하였던 아키텍처 예외는 해당 legacy 경로와 함께 제거한다. 기존 마이그레이션 SQL과 운영 DB의 이력은 수정하지 않는다. 알려진 과거 checksum 예외는 기존 `docs/operations/README.md` 기록을 참조한다.

## DB 및 런타임 호환성

Phase 2 런타임은 Phase 1 DB에서 실행할 수 없다. `release-migrate assert-runtime phase2`는 전체 expand 이력과 `20260822000000_canonical_asset_contract`의 정상 완료 기록을 모두 요구한다. contract 적용 후에는 Phase 1 런타임으로 복귀할 수 없으며 기존 전진 복구 절차를 적용한다.

#49 병합은 이미지 빌드를 수행하지만 운영 전환을 실행하지 않는다. #49의 별도 배포는 필수 조건이 아니다. #50까지 검토·통합한 뒤 최종 master 이미지로 한 번 전환할 수 있으나, 후속 마이그레이션에 맞는 아티팩트 검증과 전환 검증을 다시 수행해야 한다.

## 운영 확인 근거와 미확인 조건

2026-09-10 통합 검토 시 확보한 근거는 다음과 같다.

- CD 실행 `34327945210`은 source `d103504a004b9b04e174a7483810c4d0568ff32f`, image digest `sha256:6e00b4adfda6ac51095b7d91ce60e8d842fe6f9a89bf8242b3e21c0c398904c0`, `expand=true`, `contract=false`를 기록하였다. 이는 CD 로그 근거이며 현재 컨테이너를 직접 조회한 결과는 아니다.
- 공개 Pages의 `release-sha.txt`도 같은 소스 커밋을 반환하였다. API health는 `2026-09-09T15:39:12Z`에 ready/DB 정상으로 응답하였다. 해당 health 확인은 TLS 인증서 검증을 생략한 접근이므로 인증서 정상 여부를 입증하지 않는다.
- 기존 관측 시작 기록은 `2026-09-09T06:38:04Z`이다. 위 확인 시점에는 약 9시간이 경과하여 24시간 조건이 충족되지 않았다. 이후 운영 이미지가 변경되었으므로 실제 서버의 관측 기록과 현재 이미지·소스의 일치 여부를 다시 확인해야 한다.
- 저장소 및 production 환경 변수 조회에서 `PAGES_DEPLOY_ACTOR`를 확인하지 못하였다. Pages 보호 설정 조회는 404를 반환하여 설정의 부재와 접근 권한 부족을 구분할 수 없다. 기존 Phase 2 CD의 Pages 조건은 미확인 상태이다.

배포 전에는 현재 이미지와 일치하는 관측 기록과 24시간 동안 값이 0인 legacy fallback 지표, 자산 대조·정리 상태, DB 백업, 저장 용량, Pages 제어 조건 및 최종 master의 검증된 불변 이미지를 확인해야 한다. 이 통합 작업은 운영 설정 변경, 관측 기록 초기화, 마이그레이션 또는 배포를 실행하지 않는다.

## 검증 구성

기본 테스트·빌드·린트·아키텍처 검사 외에 다음 검증을 포함한다.

- 기존 contract SQL의 정상 전환, 부정합 데이터의 원자적 거부, 동시 쓰기 잠금 검증
- 실제 PostgreSQL·Garage를 이용한 자산 이전과 게시 처리 검증
- 실제 DB 세션 쿠키로 관리자 조회·수정 및 공개 조회의 빈 첨부 목록·비어 있지 않은 첨부 목록 검증
- 자료 첨부·영상 순서 검증과 격리 DB의 전체 마이그레이션 적용
- 통합 환경의 게시 워커 및 HTTP 제출 → 비공개 DRAFT → 게시 완료 경로
- 기존 전환·복구·권한 경계 검사와 로컬 Docker 이미지 구성 검사

검증 결과와 GitHub CI 실행은 PR #49에 기록한다. 로컬 격리 DB·스토리지 결과와 운영 검증은 구분한다.
