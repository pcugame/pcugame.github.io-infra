# 한국 웹 혐오·논란 표현 DB

첫 조사에서 의미군 후보 111개를 검토하여 71개를 채택하고, 36개를 보류하고, 4개를 제외하였다. 표기 변형을 포함한 120개 표기를 111개 의미군으로 관리한다. 채택 수나 유형별 비율을 채우기 위한 자동 확장은 수행하지 않았다. 후속 조사에서는 건수 제한 없이 근거를 추가한다.

## 조사 범위와 판정

국내 게임 프로필·커뮤니티 게시물, 게임 경험 기록, 보도 및 연구의 표현 목록을 대조하였다. 성별·성적 지향, 인종·국적·지역, 장애·질병·외모, 주거·소득, 참사·고인, 폭력·성적 가해, 역사·정치와 게임 은어를 포함한다. 일반 독법이 가능한 말도 보존한다. 개별 출처의 정확한 표기 확인과 그 표기의 의미 해석은 별도로 기록한다.

100~150개는 첫 조사의 검토 범위이며 검증된 표현의 할당량이 아니다. 경험조사에 수록되었으나 의미가 설명되지 않은 표현과 검색용 키워드는 보류하였다. 이때 해석 후보는 편집자의 가설이며 출처가 확정한 뜻으로 사용하지 않는다. 조사 단서는 후속 검색에 사용할 문자열이며, 각 문자열로 독립 검색을 수행하였다는 실행 기록은 아니다. 실제 검토 위치는 각 근거의 `locator`에 기록한다.

| 결정 | 의미 | 확정 평가 연결 |
| --- | --- | --- |
| `accepted` · 채택 | 출처의 입증 범위 안에서 독법 또는 대상 범주를 채택 | `verified`인 경우 가능 |
| `held` · 보류 | 뜻·원문 문맥·표기 등의 추가 확인 필요 | 불가 |
| `excluded` · 제외 | 승인한 조사 범위에서 제외 | 불가 |

`verified`는 문헌·관측 근거를 검토하였다는 상태이다. 모든 사용의 혐오성, 최초 유래, 사용자의 의도나 소속을 확정한 정답은 아니다. `provisional`은 표기 등 일부 근거만 확보한 상태이며, `unverified`는 원문이 없는 제보·합성 후보의 미확인 상태이다. 별도 평가자 간 일치도와 실제 모델 성능은 미측정이다.

`전구넣고깨기`는 `ko-lightbulb`에 사용자 제보로 보존하였다. 가학·신체 위해라는 해석 후보만 기록하고 대상은 `unknown`으로 설정하였다. 원문 확인 전에는 특정 피해 집단, 성적 맥락, 유래를 확정하지 않는다. 근거 검토 사례에는 포함하지 않는다.

## 원자료 구조

| 필드 | 기록 내용 |
| --- | --- |
| `id`, `expression` | 변경하지 않는 의미군 ID와 대표 표현 |
| `variants` | 실제 확인한 표기, 관측 종류, 출처·확인 위치 |
| `interpretations` | 복수 해석 후보, 근거 수준, 해당 독법의 지칭 대상과 의미 근거 |
| `riskTypes` | 중복 지정 가능한 검토 유형 |
| `contexts` | 직접 사용·비판·인용·보도·자칭·일반 용법·기능 미확인의 구별 |
| `ordinaryReadings` | 일반 독법 또는 단정에 필요한 추가 문맥 |
| `review` | 채택·보류·제외 결정, 검토 상태, 이유, 검토일 |
| `research` | 후속 조사 단서와 현재 근거의 한계 |

같은 의미의 자모·자판·띄어쓰기 변형을 별도 의미군으로 추가하지 않는다. 변형을 관측하지 않았다면 `variants`에 생성해서 삽입하지 않는다. 예를 들어 `냄저`와 `냄져`, `병크`와 `병신크리`는 각각 한 의미군이다. 정규화 중복 검사로 확인할 수 없는 의미 중복은 편집 검토가 필요하다.

대상은 `{ "state": "identified", "label": "…" }`, `{ "state": "none", "label": null }`, `{ "state": "unknown", "label": null }` 중 하나로 기록한다. `none`은 해당 독법에서 직접 지칭하는 대상이 없다는 뜻이다. `unknown`은 대상 정보가 부족하다는 뜻이며 무해함을 뜻하지 않는다. 위험 유형과 지칭 대상 상태를 독립적으로 검토한다.

## 출처와 입증 범위

| 표기 근거 | 범위 |
| --- | --- |
| `original` | 원 게시물·프로필·당사자 에세이에서 정확한 표기 확인 |
| `reported` | 보도·연구·참고 자료에서 표기 확인; 원 게임 화면 관측과 구별 |
| `elicited` | 설문에 제시되거나 응답에 수록된 표기 |
| `user_report` | 사용자가 제보한 표기; 원문 확보 여부 별도 |
| `synthetic` | 승인 계획 등에 제시된 합성 후보 |

`original`은 원문에 그 표기가 있다는 뜻이다. 예를 들어 혐오 표현을 비판하는 당사자 에세이는 원문이지만, 에세이에 서술된 과거 게임 채팅까지 직접 확보하였다는 뜻은 아니다. 국내 학교 경험을 취재한 주거 차별 보도만 있는 경우 온라인 유통을 확인한 것으로 기록하지 않는다.

`sources.json`의 `kind`는 자료 종류, `accessStatus`는 본문 열람·검색 수록문·이전 검토 기록·제보·합성의 구별이다. `surfaceForms`는 출처에서 확인한 정확한 표기 목록이며, `nicknameForms`는 실제 닉네임으로 확인한 부분집합이다. `meaningScope`가 `candidate_only` 또는 `none`인 자료는 확정 의미의 근거로 사용할 수 없다. `target_category`는 설문 등의 대상 범주만 입증하며 상세 어원까지 입증하지 않는다. 외부 자료의 장문 원문은 복제하지 않고 주소·확인 위치·짧은 설명을 보존한다.

`contexts.use`는 그 문맥의 발화 기능이다. 보도나 논문이 직접 공격을 인용한 경우에는 그 관계를 설명에 기록한다. 발화 기능이 다른 근거는 별도 문맥으로 추가한다. 인용된 표현이나 사건 언급만으로 작성자의 가해, 정치 성향, 커뮤니티 소속을 추정하지 않는다.

## 검증과 재생성

저장소 루트에서 실행한다.

```sh
npm run build -w @pcu/contracts
node benchmarks/nickname-evaluation/curated/build.mjs --write
node benchmarks/nickname-evaluation/curated/build.mjs
node --test benchmarks/nickname-evaluation/expressions/validate.test.mjs
```

`--write`는 표현 DB의 탐색 문서·집계와 닉네임 조사 자료의 사례 문서·출처 부분집합을 재생성한다. 기본 명령은 원자료와 생성 파일의 정확한 일치를 확인한다. 표현 DB만 검사하려면 `node benchmarks/nickname-evaluation/expressions/build.mjs`를 실행한다. 이 검사는 workspace 설치가 필요 없다.

검증기는 UTF-8, ID·표기 중복, 출처·의미군 참조, 관측 종류와 출처의 일치, 제보·후보 전용 근거의 확정 의미 전환, 대상 상태, 닉네임 단서·아나그램, 닉네임 형식과 생성 파일의 일치를 검사한다. `confirmed` 조사 항목은 채택·근거 검토 상태인 의미군에만 연결할 수 있다. `exploratory` 항목은 검토 문서에는 보존할 수 있으나 근거 검토 목록에는 포함하지 않는다.

출처의 내용과 해석이 실제로 부합하는지는 편집 검토 대상이다. 자동 검증은 의미 판단이나 외부 URL의 지속적인 가용성을 보장하지 않는다. 출처 재확인 결과가 변경되면 먼저 검토 상태와 연결된 조사 항목을 조정한 뒤 재생성한다.

Lab 데이터셋에는 사람이 기대 근거·위험 점수를 작성한다. 이 조사 DB는 근거 작성 자료이며 모델에 제공하는 사용 문맥이나 별도 데이터셋 유형이 아니다. [닉네임 평가 양식](../README.md)을 사용한다.
