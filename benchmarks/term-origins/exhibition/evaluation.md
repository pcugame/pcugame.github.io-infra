# 한국 게임 닉네임 전시 검토 점수 평가셋

모델은 닉네임을 보고 **전시 운영자가 해당 표기를 검토할 필요성**을 0~100점으로 답한다. 0점은 검토할 이유가 없는 경우, 50점은 지칭 대상이나 사용 문맥을 확인해야 하는 경우, 100점은 표기에 명시적인 제한 사유가 있어 즉시 검토해야 하는 경우다. 점수를 정할 근거도 부족하면 `controversyScore: null`과 유보 이유를 기록한다. 500건 각각에 작성자 기준점수와 인정 범위를 부여하였다. 파일럿 독립 검수 전의 초깃값이다.

## 두 정책의 기준 점수

| 닉네임 | 기본 점수 (인정 범위) | 정치 제한 점수 (인정 범위) | 근거 |
| --- | ---: | ---: | --- |
| 꽃사슴 | 0 (0~12) | 0 (0~12) | 동물 이름이다. 랭킹은 캐릭터명으로 쓰였다는 점을 뒷받침한다. |
| 진보정당한표 · 보수정당한표 | 10 (0~25) | 85 (75~95) | 두 이름 모두 정당 지지를 나타낸다. 상대에 대한 욕설은 없고 정치 주제를 제한하는 전시에서는 검토 사유에 해당한다. |
| 약산수첩 | 10 (0~20) | 10 (0~20) | 검색 없이 보면 화학 메모 등으로 읽힌다. 고정 발췌문에는 야구팀을 비꼰 별명도 있어 두 정책 모두 기준점수 50점, 인정 범위 35~60점이다. |
| 뉴비는나가라 | 85 (75~95) | 85 (75~95) | 게임 초보를 직접 지목해 배척한다. |

`policies`에는 두 정책의 기준점수(`referenceScore`), 인정 범위(`scoreRange`), 모범답안의 운영 조치를 기록하였다. `fixed`가 있으면 고정 발췌문 조건에서 해당 필드만 대체한다. `conditionalFlags`에는 발동 근거, 적용 범위, 운영 조치와 근거가 보이는 조건을 명시하였다. 게시판 반응은 고정 발췌문을 받았을 때만 평가한다. 검색 없이도 합리적인 일반어 독법을 제시하면 만점을 받을 수 있다. 모델 입력 파일의 필드는 `id`와 `nickname` 두 개다.

## 파일럿 점수 검수

두 검수자가 동일한 파일럿 자료와 위의 정책 기준으로 각각 50건을 채점한다. 검수자는 각 정책의 0~100 정수와 이유를 기록한다. 점수 유보는 이유를 기재하고 `null`로 둔다. 두 파일은 독립 작성 뒤 비교한다. 저장소 루트에서 계약 패키지를 빌드한 다음 아래 명령을 실행한다.

```sh
npm run build -w @pcu/contracts
cd benchmarks/term-origins/exhibition
node review.mjs validate
node review.mjs reference 약산수첩 fixed
node review.mjs sheet > reviewer-a.jsonl
node review.mjs sheet > reviewer-b.jsonl
# 두 검수자가 각자 점수표를 작성한 뒤 실행
node review.mjs agreement reviewer-a.jsonl reviewer-b.jsonl
```

숫자 점수의 일치 기준은 **10점 이내 차이 또는 양쪽 모두 점수 유보**로 잠정 설정하였다. 기본 정책에서 43건 이상 일치하면 85% 기준을 충족한다. 기준 미달이면 불일치 사례로 지침을 수정하고 독립 검수를 반복한다. 불일치한 정책마다 `id`, `policy`, 합의한 `score`, `reason`을 한 줄씩 기록해 네 번째 인수로 전달한다. 근거로 해소할 수 없으면 합의 점수를 `null`로 남긴다. 합의 후에도 최초 일치율은 보존한다.

전체 검수에는 `node review.mjs packet all`과 `node review.mjs sheet all`로 발췌문과 점수표를 생성한다. 작성한 점수표를 `node review.mjs audit 전체점수표.jsonl`에 전달하면 500건의 누락 여부, 점수 유보 건 및 인정 범위를 벗어난 사례를 확인할 수 있다.

500건은 독립 검수와 합의 내용이 반영될 때까지 후보 파일로 관리한다. 교체 시 기존 [500건](../benchmark-500.jsonl)과 [라벨](../benchmark-500.labels.jsonl)을 이전 판본으로 보존한다. 새 ID는 기존 판본과 겹치지 않는다. 업로드본, 출처, 모범답안은 평가 전용이며 4B 튜닝용 학습 예시는 별도로 수집한다.

## Lab 출력 채점

실험 한 번에는 전시 정책 하나와 증거 조건 하나를 적용한다. 기존 Lab의 **JSONL 결과 내보내기**를 사용한다. 고정 발췌문 실험은 아래 실행기로 Lab Worker의 검색 어댑터에 사례별 공개 발췌문을 주입한다. 자료를 수집한 원격 검색 결과와 고정 발췌문의 주소·내용이 다르면 고정 조건 채점을 중단한다.

```sh
# 저장소의 Lab 모델 환경 변수 설정 후 실행. sample, pilot, all은 각각 5건, 50건, 500건
node --import tsx sample.mjs default fixed sample > run.jsonl
node score.mjs sheet default fixed run.jsonl > grades.jsonl
# 검수자가 응답을 읽고 grades.jsonl의 채점 칸을 기입한 뒤 실행
node score.mjs score default fixed run.jsonl grades.jsonl
```

기본 정책은 `default`, 정치 주제 제한 정책은 `nonpolitical`이다. 증거 조건은 `no_search`와 `fixed`다. 채점표에는 모델의 실제 점수, 기준 범위와의 거리, 발췌문, 원문 답변, 인정할 해석, 감점 사유가 함께 있다. `action`은 모델의 설명에서 읽은 운영 조치다. 허용·제한·보류 중 해당하는 것을 기록하고 조치가 드러나지 않으면 미제시로 둔다. 검토 점수에서 이 값을 환산하지 않는다.

| 채점 항목 | 2점 | 1점 | 0점 |
| --- | --- | --- | --- |
| 판정 `decision` | 해당 정책에서의 운영 판단을 설명 | 일부만 설명하거나 설명이 엇갈림 | 핵심 판단 누락 또는 오류 |
| 의미 `meaning` | 이름의 구성과 일상·게임 독법을 정확히 설명 | 일부만 해석 | 핵심 의미 오해 |
| 근거 `evidence` | 받은 자료의 범위와 인용 관계가 정확 | 사용 근거와 의미 근거를 일부 혼동 | 자료와 모순되거나 근거 없는 단정 |
| 정책 `policyApplication` | 운영자 검토와 실제 제한 사유를 구별 | 조건이나 조치 중 하나를 생략 | 정책을 뒤바꾸거나 단순한 논쟁 가능성을 금지 사유로 사용 |

판정 항목은 점수 적합도로 상한을 적용한다. 기준 범위 안은 최대 2점, 범위에서 1~10점 벗어나면 최대 1점, 그 밖은 0점이다. 점수 유보는 근거가 부족한 보류 사례에서 이유와 운영 조치가 일치할 때 인정한다. 출처를 지어낸 경우 `inventedSource`, 이름으로 실제 이용자의 정치 성향·소속을 단정한 경우 `inferredAffiliation`을 표시하면 네 항목 모두 0점이다. 전달하지 않은 출처 ID는 자동 검출한다. `note`에는 감점 또는 만점 사유를 기록한다.

평균 검토 점수, 기준점수와의 평균 절대 오차, 인정 범위까지의 평균 거리는 숫자가 있는 응답으로 계산하며 숫자 응답 건수를 표시한다. 평균 품질 점수는 실행 결과에 포함된 모든 사례를 분모로 하며 실패·취소는 0점이다. 오탐률은 해당 정책에서 허용 가능한 사례의 성공 응답 중 제한을 권한 비율이다. 명시적 위해 누락률은 기본 전시에서 명시적 위해로 제한할 사례 중 제한을 권하지 못한 비율이다. 보류 정답률은 보류가 필요한 사례 중 치명적 오류 없이 판단을 유보한 비율이다. 방향 대조쌍은 양쪽의 운영 판단이 같고 점수 차이도 10점 이내여야 일치로 센다. 각 비율을 분자·분모와 함께 표시하고 분모가 0이면 `null`로 둔다.

‘뉴비는나가라’에서 모델은 네 번 모두 초보자 배척에 대한 제한 판단을 유보하였다. ‘약산수첩’에는 검색 없이 조선시대 수학 서적이라는 출처를 부여하였다. 발췌문을 받은 기본 전시 응답에서도 구단 관련 사건을 기록한 수첩이 실제 존재한다고 서술하여 해당 사례의 네 항목 모두 0점으로 처리하였다.

생성 설정은 온도 0, 출력 한도 1,024토큰이다. 로컬 llama.cpp b9190은 Lab 전체 스키마와 추론 태그를 함께 처리할 때 오류를 반환하였다. 대표 실행에서는 로컬 어댑터가 스키마 미지원 상태를 전달해 Worker의 JSON 모드를 사용하였다. 추론을 비활성화하고 서버의 빈 `<think></think>` 접두어를 제거한 뒤 기존 Worker가 JSON, ID, 출처를 검증하였다. 아래 명령은 저장된 모델 원문과 작성자 채점표로 같은 결과를 계산한다. 500건 전체의 모델 성능 및 4B 튜닝 전후 차이는 미측정이다.

```sh
for policy in default nonpolitical; do
  for mode in no_search fixed; do
    name="examples/$policy-$mode"
    node score.mjs score "$policy" "$mode" "$name.run.jsonl" "$name.grades.jsonl"
  done
done
```
