# 닉네임 의미 해석 평가셋

[사례별 해석과 채택 이유](cases.md) · [수작업 원자료](cases.json) · [모델 입력](nicknames.jsonl) · [출처 부분집합](sources.json) · [표현 DB](../expressions/README.md)

표현의 표면과 사회적 의미를 구별하는 22건의 평가 사례이다. 기존 16건 초안에서 해외 상징에 의존한 3건과 수학 괄호 대조군을 제외하고, 국내 용례를 참고한 합성 닉네임 10건을 추가하였다. 모든 사례에 근거가 되는 `meaningGroupIds`를 연결하였다. 기존 500건에서 표본을 추출하거나 표현 DB 전체를 자동으로 닉네임화하지 않는다.

## 평가 기준

- `probe` · 의미 탐지: 지칭 대상·사건·단어 관계를 연결하여 위험한 독법을 설명한다. 대상이 `unknown`이어도 폭력 암시를 무해하다고 판단하지 않는다. `none`인 비유도 검토할 수 있다.
- `ambiguous` · 판단 유보: 복수 독법을 설명하고 구별에 필요한 추가 문맥을 제시한다.
- `control` · 오탐 점검: 이름에 드러난 음식·게임·학습·인사 또는 비판적 인용의 단서를 반영한다. 숨겨진 사용자 상황을 정답으로 요구하지 않는다.

문자열의 의미와 이용자의 신원·성향·소속을 구분한다. 사건을 언급하였다는 이유로 가해나 참여를 확정하지 않는다. 비판·보도·인용·자칭과 직접 공격을 구별한다. 점수 정답이나 자동 차단 판정은 부여하지 않는다. 실제 모델 성능은 미측정이다.

관측 닉네임 2건, 관측 표현 2건, 합성 이름 18건이다. 표기 관측과 의미 근거는 별도 필드이다. 합성 이름의 전체 표기나 작성 의도를 출처가 관측한 것으로 처리하지 않는다. 원문이 없는 `전구넣고깨기` 제보는 표현 DB의 보류 기록에만 보존한다.

## 입력과 검토 자료

`cases.json`이 평가셋 원자료이며, 출처의 기준 파일은 `../expressions/sources.json`이다. 이 디렉터리의 `sources.json`은 사용한 출처만 출력한 생성 파일이다. 수정은 기준 파일에서 수행한다.

모델에는 `nicknames.jsonl`의 `id`와 `nickname`만 제공한다. 역할·대상·의미군·해석·출처는 검토 자료이며 입력에 포함하지 않는다. `evaluation: confirmed`인 항목만 출력하고, 보류·제외·미확인 의미군의 연결은 거부한다. `exploratory` 항목은 확정 평가 입력에서 제외한다. 검색 근거를 제공하는 실험은 이름만 제공하는 실험과 별도로 기록한다.

## 검증 명령

```sh
npm run build -w @pcu/contracts
node benchmarks/term-origins/curated/build.mjs --write
node benchmarks/term-origins/curated/build.mjs
node --test benchmarks/term-origins/expressions/validate.test.mjs
```

검증은 UTF-8, 개별 Lab 행의 스키마, 중복·의미군 참조, 관측·합성 구분, 단서의 문자열 포함, 아나그램, 근거 상태 및 생성 파일 일치를 확인한다. 문헌의 의미 해석과 사례의 적합성은 편집 검토 대상이다.

현재 Lab 웹 업로드에는 500행 고정 조건이 있다. 22건 파일의 개별 행 검증 통과는 웹 업로드 가능을 뜻하지 않는다. 이 작업에서는 공개 API·운영 DB·업로드 조건을 변경하지 않았다.
